## 1) สัญญาฟิลด์บน `posSales` — เช็คทีละช่อง

### 1.1 ฟิลด์พื้นฐานบิล (ของเดิมต้องไม่พัง)

- [ ] `billNo`
- [ ] `subtotal`
- [ ] `discountBaht` (รวม)
- [ ] `total` = `subtotal - discountBaht`
- [ ] `paymentMethod` ∈ cash / promptpay / transfer
- [ ] `cashReceived` / `change` เมื่อเงินสด
- [ ] `sessionId` / `deviceId` / `shift` / `createdAt` / `status`

### 1.2 ฟิลด์สมาชิก / แต้ม (ต้องเขียนเมื่อเข้าเงื่อนไข)

- [ ] `memberId` เมื่อผูกสมาชิกหรือแลกหรือ earn จากขาย
- [ ] `memberPhone` เมื่อมี (โชว์บนสลิป/หลังร้าน)
- [ ] `manualDiscountBaht` — ส่วนลดมืออย่างเดียว (บิลใหม่; บิลเก่า derive ได้)
- [ ] `redeemBaht` เมื่อแลก (> 0)
- [ ] `pointsRedeemed` เมื่อแลก (> 0) และสอดคล้องสูตรกับ `redeemBaht`
- [ ] `pointsEarned` หลัง commit เมื่อมี earn จากขาย
- [ ] `pointsClaimed` / `claimStatus` / `claimToken*` คงของ QR สะสม (คนละทาง)

### 1.3 ความสัมพันธ์ตัวเลข (assert ทุกบิลเทส)

- [ ] `manualDiscountBaht >= 0`
- [ ] `redeemBaht >= 0`
- [ ] `discountBaht == manualDiscountBaht + redeemBaht` (หลัง D1)
- [ ] `total == subtotal - discountBaht`
- [ ] `redeemBaht` ไม่เกินยอดที่เหลือหลังหักส่วนลดมือ
- [ ] `pointsRedeemed` ไม่เกินแต้มคงเหลือก่อนตัด
- [ ] ถ้า `pointsRedeemed == 0` แล้ว `redeemBaht == 0`
- [ ] ถ้าไม่มีสมาชิก แล้วไม่มี `pointsRedeemed` / `redeemBaht` / `pointsEarned` จากขาย

### 1.4 Mapper อ่านครบ

- [ ] `src/lib/types.ts` — `PosSale` มีฟิลด์ครบ
- [ ] `pos-sales-report.mapPosSale` อ่านสมาชิก/แต้ม/redeem/manual
- [ ] `pos-sales-admin.mapPosSale` อ่านสมาชิก/แต้ม/redeem/manual (ไม่เฉพาะ claim)
- [ ] local receipt / sync types รับฟิลด์ที่สลิปต้องพิมพ์
- [ ] สคริปต์เทส/guard มี assert ฟิลด์สำคัญ

## 3) สลิปพิมพ์ — เช็คบรรทัด

### 3.1 เมื่อมีสมาชิก (ไม่จำเป็นต้องแลก)

- [ ] ไม่บังคับโชว์ยอดแต้มคงเหลือบนสลิป (optional — ถ้าโชว์ต้องไม่ผิด)

### 3.2 เมื่อมีแลกแต้ม

- [ ] มีบรรทัดชัด: แลกแต้ม / ส่วนลดจากแต้ม
- [ ] โชว์บาทที่ลด (`redeemBaht`)
- [ ] โชว์จำนวนแต้มที่ตัด (`pointsRedeemed`) หรือเทียบเท่าอ่านรู้เรื่อง

- [ ] ชำระ/เงินทอนตรงยอดหลังลด

### 3.3 เมื่อมีส่วนลดมือ + แลกแต้ม

## 5) แดชบอร์ด `/pos-sales` แท็บแดชบอร์ด

### 5.1 ตัวเลขที่ต้องคง (regress)

- [ ] ยอดขายสุทธิ = `Σ total` completed ในช่วงวันที่
- [ ] แยกช่องทาง cash / promptpay / transfer จาก `total`
- [ ] จำนวนบิล / บิลยกเลิกยังถูก
- [ ] กราฟรายวัน/ชั่วโมงยังใช้เงินจริง (`total`) ไม่บวก redeem กลับ

### 5.2 ตัวเลขส่วนลดที่ต้องแยก

- [ ] ส่วนลดรวม (`Σ discountBaht`) ยังมี
- [ ] ส่วนลดมือ (`Σ manualDiscountBaht` หรือ derive) แยกได้
- [ ] แลกแต้มบาท (`Σ redeemBaht`) แยกได้
- [ ] จำนวนบิลที่มีแลกแต้ม
- [ ] (optional) รวมแต้มที่ตัด `Σ pointsRedeemed`
- [ ] (optional) รวมแต้มที่ให้ `Σ pointsEarned`
- [ ] ตรวจมือ: ผลรวม redeem บนแดชบอร์ด = ผลรวมบิลตัวอย่างในช่วงเดียวกัน

### 5.3 UI แดชบอร์ด

- [ ] กล่องสรุปไม่ทำให้เข้าใจว่าแลกแต้มเป็นยอดขาย
- [ ] มีแถวหรือกล่องชัดคำว่า «แลกแต้ม» / loyalty
- [ ] ไม่โชว์ช่องทางชำระชื่อแต้ม
- [ ] อัปเดตหมายเหตุใน `pos-sales-dashboard-phases.md` เมื่อแยกส่วนลดแล้ว
- [ ] ช่วงวันที่ไม่มีบิลแลกแต้ม → แสดง 0 ไม่พัง

### 5.4 พื้นผิวสรุปอื่นที่แตะยอด (อย่าพลาด)

- [ ] สรุปรอบขาย / ตาราง sessions — ส่วนลดรวมไม่ตัด redeem หาย
- [ ] พิมพ์ X / Z — ยอดเงินสดตรงลิ้นชัก
- [ ] ถ้า Z โชว์ส่วนลด — ระบุหรือรวม redeem อย่างตั้งใจ
- [ ] VAT / storefront ถ้านับ `sale.total` — เข้าใจว่า redeem ลดยอดร้าน (เหมือนส่วนลด) · ไม่ต้องแก้ถ้าไม่ต้องการแยกใน VAT รอบนี้
- [ ] สินค้าขายดี / กราฟสินค้า — ไม่เอา redeem ไปบิดจำนวนชิ้น
