## ค่าที่ล็อกแล้ว (ร้าน)

| หัวข้อ | ค่า |
|--------|-----|
| สะสมแต้ม | จาก **ยอดชำระ (`total`)** หลังหักแลกแต้ม · เรทปรับได้ที่หลังร้าน · เป้า ~3% เมื่อตั้งเรทเหมาะสม |
| แลกแต้ม | **1 แต้ม = 1 บาท** (`pointsPerBahtRedeem = 1`) |
| สุทธิ 0 หลังแลกเต็มบิล | **อนุญาต** · ยังพิมพ์ QR |
| ใครใช้ได้ | **พนักงานทุกคนที่ขาย** |
| บนสลิป | **ชื่อ + เบอร์** เมื่อมีสมาชิก |
| แดชบอร์ด | โชว์ทั้ง **แต้มที่ได้** และ **แต้มที่ตัด** (+ บาทแลกแต้ม) |
| พักบิล | **พกสมาชิก** · รีเฟรชแต้มตอนดึงกลับ · เคลียร์จำนวนแต้มที่เลือกไว้ |
| QR บนสลิป | **ทุกใบ** (A1) — มี/ไม่มีสมาชิก · 0 แต้มก็พิมพ์ · สแกนแล้วเข้าเคลมหรือหน้าสมาชิก |
| ลำดับเฟส | **P0–P7** ดู [members-round-phases.md](./members-round-phases.md) |

หลังร้านต้องมีช่องปรับเรทสะสม/แลกอยู่แล้วที่ `/members` ตั้งค่า — รอบโค้ดให้คำอธิบายชัดว่า ~3% หมายถึงอะไร

## หลัก logic ชำระเงิน (มาตรฐานที่ถูกต้อง)

**ใช่ — ใช้แต้มก่อนเลือกเงินสด/โอน**

ลำดับเงินบนบิล:

```text
ยอดสินค้า (subtotal)
  − ส่วนลดมือ (ถ้ามี)
  − แลกแต้ม (redeemBaht)
  = ยอดสุทธิที่ต้องรับเงิน (total)
       ↓
  เลือกช่องทางรับเงิน: เงินสด / โอน (/ PP ถ้าเปิด)
```

- แต้ม = **ส่วนลด** ไม่ใช่ปุ่มชำระคู่กับเงินสด
- เงินสด/โอน รับเฉพาะ **ยอดที่เหลือหลังแต้ม**
- ถ้าแลกจน `total = 0` → ปิดบิลได้โดยไม่ต้องรับเงินสด/โอน (ตามที่ล็อก)

ของเดิมบนจอขาย: มี **คิดเงินรวม (pay all)** เป็นทางเข้าหลัก · ปุ่มเงินสด/โอนแยกอาจซ่อนอยู่ในขั้นถัดไป — ออกแบบด้านล่างให้เข้ากับโครงนี้

## ปุ่มและสเต็ปบนจอ (ออกแบบ)

### แถบตะกร้า (ก่อนกดคิดเงิน)

| ปุ่ม / องค์ประกอบ | เมื่อโชว์ | ทำอะไร |
|-------------------|----------|--------|
| **สมาชิก** | ธงสมาชิกเปิด | เปิดคีย์เบอร์ → lookup → ติดบิล |
| แถบสมาชิก (ชื่อ · แต้ม) | มีสมาชิกบนบิลแล้ว | โชว์สถานะ |
| **ใช้แต้ม** | มีสมาชิก + แต้ม > 0 + ยอด > 0 | เปิดจอเลือกแต้ม |
| **ถอด** | มีสมาชิก | ถอดสมาชิก + เคลียร์แต้มที่เลือก |
| ส่วนลด (ของเดิม) | เหมือนเดิม | ส่วนลดมือ — คนละปุ่มกับใช้แต้ม |
| **คิดเงิน** (pay all ของเดิม) | มีของในตะกร้า | เข้าขั้นชำระ |

อย่าใส่ «จ่ายด้วยแต้ม» เป็นช่องทางคู่เงินสด — จะสับสนและเพี้ยนลิ้นชัก

### สเต็ปแนะนำ (สั้น พนักงานไม่หลง)

```text
[1 ตะกร้า]
  ใส่เมนู → (ถ้ามี) สมาชิก → (ถ้ามี) ใช้แต้ม → (ถ้ามี) ส่วนลดมือ
       ↓ กด «คิดเงิน»
[2 สรุปก่อนรับเงิน]
  โชว์: ยอดก่อนลด · ส่วนลดมือ · แลกแต้ม · สุทธิ
  ถ้ายังไม่มีสมาชิก: ปุ่มรอง «ใส่สมาชิก» (optional ไม่บังคับ)
  ถ้ามีสมาชิกยังไม่ใช้แต้ม: ปุ่มรอง «ใช้แต้ม»
       ↓
[3 รับเงิน]  — เฉพาะเมื่อสุทธิ > 0
  ปุ่มหลักใหญ่:
    · เงินสด
    · โอน
  (PromptPay ถ้าเปิดใช้ในร้าน — คนละปุ่ม)
       ↓
[4 ยืนยัน]
  เงินสด → คีย์รับเงิน / ทอน
  โอน → ยืนยันตาม flow เดิม
  สุทธิ 0 → ปุ่มเดียว «ปิดบิล» (ไม่ถามรับเงิน)
       ↓
พิมพ์สลิป · เคลียร์ตะกร้า
```

### Logic กันพลาด (ต้องมี)

- [ ] ใช้แต้มได้เฉพาะหลังมีสมาชิกบนบิล
- [ ] จำนวนแต้ม ≤ คงเหลือ (รีเฟรชตอนเปิดจอใช้แต้ม)
- [ ] บาทที่ลดจากแต้ม ≤ ยอดหลังหักส่วนลดมือ
- [ ] เปลี่ยนส่วนลดมือหลังเลือกแต้มแล้ว → คำนวณเพดานแต้มใหม่ / ตัดแต้มที่เลือกให้ไม่เกิน
- [ ] ถอดสมาชิก → เคลียร์แต้มที่เลือก
- [ ] สุทธิ 0 → ข้ามขั้นรับเงิน · ยังพิมพ์สลิป
- [ ] เงินสด/โอน คิดจากสุทธิหลังแต้มเท่านั้น
- [ ] ปิดบิลล้ม → แต้มยังไม่ตัด
- [ ] บิลถัดไปไม่ค้างสมาชิก/แต้มเก่า

### ตัวอย่างตัวเลขบนจอ

ตะกร้า 120 · ส่วนลดมือ 0 · ใช้ 40 แต้ม (1:1):

| แถว | บาท |
|-----|-----|
| รวมสินค้า | 120 |
| แลกแต้ม (40 แต้ม) | −40 |
| **สุทธิ** | **80** |

→ ปุ่มเงินสด/โอน รับ **80** ไม่ใช่ 120

| นโยบาย | ค่า |
|--------|-----|
| พักบิล | **เก็บสมาชิกที่ติดบิลไว้** |

| จำนวนแต้มที่เคยกดใช้ | **ไม่พก** — ให้กดใช้แต้มใหม่ (กันแต้มเปลี่ยนระหว่างพัก) |

## สลิป — สมาชิก / แลกแต้ม / QR ท้ายบิล

### โครงสลิป (บน → ล่าง)

1. หัวร้าน / เลขบิล / เวลา (ของเดิม)  
2. รายการสินค้า (ของเดิม)  
3. รวมสินค้า  
4. ส่วนลดมือ (ถ้ามี)  
5. **แลกแต้ม −X บาท (Y แต้ม)** (ถ้ามี)  
6. **ยอดสุทธิ**  
7. ชำระ / รับเงิน / ทอน (ของเดิม · ข้ามถ้าสุทธิ 0)  
8. **สมาชิก: {ชื่อ} · {เบอร์}** (ถ้ามีสมาชิก)  
9. (ว่างเล็กน้อย)  
10. **QR สะสมแต้ม** (เมื่อธงพิมพ์ QR เปิด — R3)  
11. ข้อความเชิญสั้นใต้ QR  
12. ท้ายสลิปของเดิม (ขอบคุณ ฯลฯ ถ้าร้านมี)

### QR ท้ายบิล (มาตรฐานสลิปทั่วไป)

| ข้อ | ค่า |
|-----|-----|
| ตำแหน่ง | **ท้ายบิล** หลังยอด/สมาชิก · ก่อนหรือแทนท้ายกระดาษสั้นๆ |
| ขนาด | **กลาง** — เป้าประมาณ **180–220 px** บนหัวพิมพ์ 58mm (ไม่ใหญ่กินกระดาษ ไม่เล็กจนสแกนยาก) |
| เนื้อ QR | ลิงก์ `/claim/?s={saleId}&t={token}` ชุดเดียวกับหลังร้าน |
| เมื่อพิมพ์ | ธงพิมพ์ QR เปิด → **ทุกใบ** แม้ไม่มีสมาชิก · แม้สุทธิ 0 · แม้แต้มสะสมคำนวณได้ 0 |
| เมื่อไม่พิมพ์ | ธงปิด → สลิปจบแบบเดิม ไม่เว้นช่องว่างใหญ่ |
| แต้มจาก QR | จากยอดชำระ (`total`) = ยอดขายหลังหักแลกแต้ม |
| สแกนได้ 0 แต้ม / ใช้แล้ว | ไม่ตัน → พาไปหน้าสมาชิก (`/me` / เข้าสู่ระบบ) |

### คำใต้ QR (พอประมาณ เชิญ ไม่ยาว)

บรรทัดหลัก (หนา/กลาง):

```text
สแกนสะสมแต้ม
```

บรรทัดรอง (เล็กกว่า 1–2 บรรทัด):

```text
รับแต้มเข้าบัญชี · ใช้ลดได้ครั้งถัดไป
```

ทางเลือกสั้นกว่าถ้าพื้นที่แน่น:

```text
สแกนรับแต้ม TellTea
```

- ไม่ใส่ URL ยาวใต้ QR (QR  suffices)  
- ไม่ใส่โปรโมยาวหลายบรรทัด  
- ถ้าบิลเคลมไม่ได้ (0 แต้ม) → ไม่พิมพ์ QR

### เมื่อมีแลกแต้มบนบิลเดียวกัน

- พิมพ์บรรทัดแลกแต้มด้านบนตามปกติ  
- QR ท้ายบิล**ยังพิมพ์** แม้สุทธิ 0 / แต้มสะสม 0  
- แต้มที่จะได้ตอนสแกน (ถ้า > 0) คิดจากยอดชำระหลังแลกแต้ม
