## เป้าปลายทาง

จากไฟล์ Excel / PDF ต่อช่องทาง → แถววันไม่ซ้ำ → รวมเข้าเดือน:

| ผลลัพธ์ | ไปที่ |
|--------|--------|
| ยอดขายจริง (gross) | ภาษีขาย · ช่องทาง Shopee / Grab / LINE MAN |
| ยอดโอนจริง (net transfer) | ตาราง GP ช่องทาง → คชจ. P&L |
| ภาษีซื้อ GP จริง + เลขที่ใบกำกับ | ภาษีซื้อเดลิเวอรี่ |

หลักการ: **ตารางกลางมาตรฐานหนึ่งแบบ** · ความต่างของไฟล์อยู่ที่ **อะแดปเตอร์** · ไฟล์ต้นทางอยู่ใน Storage ของกิจการ

---

## ภาพรวมเฟส

| เฟส | ชื่อ | เป้า | สถานะ |
|-----|------|------|--------|
| **I0** | สัญญาตาราง + คีย์ | คอลัมน์กลาง · dedupe · ชนิดแถว | ✅ |
| **I1** | แท็บนำเข้า + ตารางเปล่า | UI คีย์มือได้ · ยังไม่ parse | ✅ โค้ดฐาน |
| **I2** | อัปโหลด → Storage | เก็บไฟล์ · ลิงก์เปิดจากแถว | ✅ โค้ดฐาน |
| **I3** | อะแดปเตอร์ไฟล์จริง #1 | parse ชนิดที่มีไฟล์ตัวอย่างบ่อยสุด | ⬜ รอไฟล์ตัวอย่าง |
| **I4** | อะแดปเตอร์เพิ่มทีละชนิด | Shopee / Grab / LM · Excel/PDF คนละตัว | ⬜ |
| **I5** | รวมเข้าเดือน | ติ๊กแถว → เติมยอดขาย / โอน / GP VAT | ⬜ |
| **I6** | ใช้จริง + ปรับ | เดือนแรกด้วยไฟล์จริง · แก้ parser | ⬜ |

อย่าเริ่ม I3 ก่อนมีไฟล์ตัวอย่างจริงอย่างน้อย 1 ชนิด

## I0 — สัญญาตารางกลาง (ทำก่อนโค้ด UI)

### ชนิดแถว (`rowKind`)

| kind | ความหมาย | ฟิลด์สำคัญ |
|------|----------|------------|
| `sales` | รายงานยอดขายรายวัน/รอบ | gross · (fee) · netTransfer |
| `transfer` | สลิป/สรุปยอดโอนอย่างเดียว | netTransfer |
| `tax_invoice` | ใบกำกับภาษีซื้อ (GP ฯลฯ) | gpVat · **invoiceNo** · invoiceDate · sellerTaxId? |

แถวหนึ่งอาจเป็น `sales` ที่พ่วง fee/net ก็ได้ — `tax_invoice` แยกเมื่อมีใบกำกับจริง

### คอลัมน์ตาราง (มาตรฐานทุกช่องทาง)

| คอลัมน์ | ใส่ใคร | หมายเหตุ |
|--------|--------|----------|
| วันที่ (`dateKey`) | ไฟล์/คน | `YYYY-MM-DD` Bangkok |
| ช่องทาง | ไฟล์/คน | `shopee` · `grab` · `lineman` · `storefront` |
| ชนิดแถว | ระบบ/คน | ตามตารางบน |
| ยอดขายรวม VAT | ไฟล์ | `grossInclusive` |
| คชจ. / GP | ไฟล์หรือคำนวณ | `fee` ≈ gross − net เมื่อมีทั้งคู่ |
| ยอดโอนหลัง | ไฟล์ | `netTransfer` |
| ภาษีซื้อ GP | ไฟล์ | `gpVat` |
| **เลขที่ใบกำกับ** | ไฟล์ | บังคับเมื่อ `tax_invoice` · อื่นว่างได้ |
| วันที่ใบกำกับ | ไฟล์ | คู่กับเลขที่ |
| ไฟล์ต้นทาง | ระบบ | ลิงก์ Storage |
| สถานะ | ระบบ | `draft` · `applied` · `skipped` |
| แหล่ง | ระบบ | ชื่ออะแดปเตอร์ + เวอร์ชัน |

### คีย์ไม่ซ้ำ (dedupe)

ลำดับลองจับ:

1. มี `externalId` จากไฟล์ → `channel + externalId`
2. มีเลขใบกำกับ → `channel + invoiceNo`
3. ไม่มี → `dateKey + channel + rowKind` (+ ยอด gross/net เป็นตัวช่วยเตือนซ้ำ)

อัปโหลดซ้ำไฟล์เดิม: ไม่สร้างแถวซ้ำถ้า hash/path ตรง

### Storage

```
vat-imports/{YYYY}/{MM}/{channel}/{uploadId}-{safeFileName}
```

แถวเก็บ: `storagePath` · `contentType` · `uploadedAt` · `uploadedBy`  
(ยังไม่ทำ Google Drive)

### Firestore (ร่าง)

```
vatImportRows/{autoId}
  monthKey, dateKey, channel, rowKind,
  grossInclusive, fee, netTransfer, gpVat,
  invoiceNo, invoiceDate, sellerTaxId?,
  storagePath, adapterId, adapterVersion,
  externalId?, contentHash?,
  status: draft|applied|skipped,
  appliedAt?, appliedToMonth?,
  createdAt, updatedAt, updatedBy
```

รีใช้แนว `ChannelAmount` จาก `vat-sales.ts` ได้ — **ไม่บังคับ** เปิด UI `dailySales` เก่ากลับมาทั้งก้อน

## I1 — แท็บนำเข้า + ตารางเปล่า

**ทำ**

- แท็บใน `/vat-sales/`: **เดือน** (หน้าปัจจุบัน) | **นำเข้า**
- ตารางกลางตาม I0 · กรองเดือน/ช่องทาง
- คีย์มือ + ลบ/ข้ามแถว
- ยังไม่ต้องอัปโหลดก็ได้ (หรือช่องไฟล์ยัง disabled)

**ไม่ทำ**

- parse · รวมเข้าเดือนอัตโนมัติ

**เสร็จเมื่อ**

- [ ] เจ้าของเห็นแท็บ · ใส่แถววัน×ช่องทางได้ · รีเฟรชแล้วยังอยู่

---

## I2 — อัปโหลด → Firebase Storage

**ทำ**

- ปุ่มอัปโหลดต่อแถวหรือต่อชุด (เลือกช่องทาง + เดือน)
- เขียน Storage path ตาม I0 · เปิดดูไฟล์จากแถว
- บันทึกเมตาไฟล์ใน `vatImportRows` (แม้ยังไม่ parse)

**เสร็จเมื่อ**

- [ ] อัปโหลด PDF/xlsx แล้วเปิดดูจากแถวได้ · ไฟล์ไม่หายหลังรีเฟรช

---

## I3 — อะแดปเตอร์ไฟล์จริงตัวแรก

**ทำ**

- รับไฟล์ตัวอย่างจริง 1 ชนิด (เช่น Grab PDF รายวัน หรือ Excel ที่ใช้บ่อยสุด)
- `adapterId` คงที่ · ทดสอบด้วยไฟล์ตัวอย่างใน repo/fixtures (ไม่มีข้อมูลลับ)
- ผล parse → แถว `draft` ให้คนตรวจก่อน apply

**เสร็จเมื่อ**

- [ ] อัปโหลดไฟล์ชนิดนั้นแล้วได้แถวถูกวัน/ยอด · dedupe ซ้ำไม่พัง

---

## I4 — อะแดปเตอร์เพิ่มทีละชนิด

ลำดับแนะนำ (ปรับตามไฟล์ที่มีจริง):

1. ช่องทางที่ใช้บ่อย / ไฟล์โครงคงที่  
2. ช่องทางถัดไป  
3. ใบกำกับภาษี GP (เน้น `invoiceNo` + `gpVat`)

กฎ: **หนึ่งอะแดปเตอร์ = หนึ่งรูปแบบไฟล์** ไม่ใช่หนึ่งช่องทางทั้งจักรวาล  
UI เลือกชนิดตอนอัปโหลด (หรือเดาแล้วให้ยืนยัน)

---

## I5 — รวมเข้าเดือน

**ทำ**

- ติ๊กแถว `draft` → **ใช้เข้าเดือนนี้**
- map:
  - Σ `grossInclusive` ต่อช่องทาง → ยอดขายเดลิเวอรี่
  - Σ/ค่าล่าสุด `netTransfer` ต่อช่องทาง → GP ช่องทาง (โหมดยอดโอน)
  - Σ `gpVat` (+ เก็บเลขใบกำกับในโน้ตหรือคอลเลกชันย่อย) → ภาษีซื้อ GP เดลิเวอรี่
- ไม่ทับทั้งเดือนมืดๆ — ทับเฉพาะช่องทาง/ฟิลด์ที่แถวครอบคลุม
- แถวที่ apply แล้ว → `applied` · แก้เดือนต้องปลดหรือ apply ใหม่ชัดเจน

**เสร็จเมื่อ**

- [ ] apply แล้วตัวเลขหน้าเดือนตรงกับ Σ แถวที่ติ๊ก · ไฟล์+เลขใบกำกับยังเปิดดูได้
