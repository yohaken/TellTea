# VAT นำเข้าไฟล์จริง — วางเฟสจนครบ

> Route: `/vat-sales/` · แท็บ **นำเข้า** + แท็บ **เดือน**  
> เก็บไฟล์: **Firebase Storage** (`vat-imports/…`)  
> เช็คลิสต์: [`vat-import-check.md`](./vat-import-check.md)  
> อัปเดต: 2026-07-29

---

## เป้าปลายทาง (นิยาม「ครบ」)

ร้านปิดเดือนได้โดย:

1. โยนไฟล์จริงต่อช่องทาง → ได้แถววันไม่ซ้ำ  
2. กด**ใช้เข้าเดือน** → ยอดขาย / ยอดโอน / ภาษีซื้อ GP ตรงไฟล์  
3. มีเลขใบกำกับ + ไฟล์ต้นทางเปิดดูได้  
4. ทำซ้ำเดือนถัดไปได้โดยไม่พังของเดิม  

| ผลลัพธ์ | แหล่งหลักที่ตั้งใจ |
|--------|-------------------|
| ยอดขาย Shopee | รายงานธุรกรรม/ยอดขาย (ยังขาดอะแดปเตอร์ขาย) |
| ยอดขาย Grab | CSV Transaction_Store (มีแล้ว · ต้องจูนหัวจริง) |
| ยอดขาย LINE MAN | รายงานประจำเดือน PDF ✅ |
| ยอดโอนหลัง (คชจ. GP) | จากรายงานวัน/เดือนต่อช่องทาง |
| ภาษีซื้อ GP + เลขที่ | Shopee ใบกำกับ ✅ · Grab/LM ใบกำกับตามที่มี |

## I0–I5 (ทำแล้ว — สรุปสั้น)

- ตารางกลางวัน×ช่องทาง · dedupe · Storage  
- อะแดปเตอร์: `lineman-monthly-pdf` · `grab-transaction-csv` · `shopee-taxinvoice-pdf`  
- ปุ่ม**ใช้เข้าเดือน** → `vatMonthlyReturns` (channels / transfer GP / delivery.gpVat)  
- รายละเอียดเดิมด้านล่างเอกสาร + เช็คลิสต์

## I6a — Storage inbox + แปลงเข้าตารางแบบเคร่ง (ทำแล้ว · โค้ดฐาน)

**เป้า:** สภาพแวดล้อมแน่นก่อน AI เติมช่องว่าง

1. ไฟล์อยู่ Firebase Storage `vat-imports/{YYYY}/{MM}/{channel}/…`  
2. ปุ่ม **ดึงไฟล์ใหม่** สแกน inbox → สร้างแถว (dedupe `storagePath` / `contentHash`)  
3. อะแดปเตอร์ที่รู้จัก (LM PDF · Grab CSV · Shopee ใบกำกับ) เติมเฉพาะช่องที่ชัวร์  
4. ไม่รู้จัก / ไม่ชัวร์ → แถว `inbox-pending` · ยอดว่าง (0) · โน้ตรอ AI/คน  

**โค้ด:** `vat-import-inbox.ts` · `vat-import-hash.ts` · ปุ่มใน `VatImportWorkbench`

---

## I6b — ตารางเดือนก่อน + บริบทบนเว็บ (ทำแล้ว · โค้ดฐาน)

**เป้า:** ออกแบบตารางรอทุกช่องทาง/คอลัมน์ก่อน แล้วค่อยให้คนหรือ local AI เติม

1. ปุ่ม **สร้างตารางเดือน** → แถวขายว่างครบวัน × Shopee/Grab/LM/หน้าร้าน  
2. แผง **บริบทตาราง** บนเว็บ: หาอะไร · ใส่อะไร ต่อคอลัมน์และช่องทาง  
3. ตาราง slim compact · hover หัวคอลัมน์ดูคำอธิบาย  
4. อัปโหลด/parse เติมเข้าช่องว่าง (upsert) ไม่สร้างแถวขายซ้ำวัน×ช่องทาง  

**โค้ด:** `vat-import-guide.ts` · `vat-import-scaffold.ts` · `VatImportWorkbench`

---

## I6 — ใช้จริง + จูนจากไฟล์ร้าน

**เป้า:** เดือนหนึ่งผ่านด้วยไฟล์ของร้านจริง ไม่ใช่แค่ fixture

**ทำ**

1. รัน [`vat-import-check.md`](./vat-import-check.md) หมวด 3–5 บน production  
2. อัปโหลดไฟล์จริงเข้า Storage → **ดึงไฟล์ใหม่** → ตรวจแถว/ช่องว่าง  
3. เอา **Grab `Transaction_Store_….csv` จริง** มาจูน `vat-import-grab-csv.ts` (ชื่อคอลัมน์จริง)  
4. เอาชุด **Shopee Taxinvoice ZIP** จริงทั้งเดือน → ตรวจ Σ gpVat  
5. LINE MAN รายงานเดือนจริง → ใช้เข้าเดือน → เทียบแท็บเดือน  
6. แก้บั๊ก/ข้อความ error ที่เจอตอนใช้จริง  


**ไฟล์ที่ต้องมีตอนแก้ทีเดียว**

- [ ] Grab CSV ช่วงเดือนจริง  
- [ ] Shopee ใบกำกับ ZIP หรือ PDF หลายวัน  
- [ ] LINE MAN รายงานประจำเดือน PDF  
- [ ] (ถ้ามี) ใบเสร็จค่าบริการ LM แยกจากรายงาน  

**เสร็จเมื่อ**

- [ ] เดือนตัวอย่างหนึ่ง: นำเข้าครบช่องทางที่มีไฟล์ → ใช้เข้าเดือน → ตัวเลขตรงตาคน  
- [ ] fixture/testdata อัปเดตตามหัว CSV จริง

## I7 — Shopee ยอดขาย (อะแดปเตอร์ขาย)

**ช่องว่างตอนนี้:** Shopee มีแค่ใบกำกับ Commission → ได้ `gpVat` อย่างเดียว ไม่มียอดขาย/ยอดโอน

**ทำ**

1. รับไฟล์ยอดขาย Shopee ที่ร้านใช้จริง (My Income / Order / transaction export — ยืนยันชนิดตอนมีไฟล์)  
2. อะแดปเตอร์ใหม่ เช่น `shopee-sales-csv` หรือ xlsx  
3. แถว `sales`: gross · fee/net ถ้ามี · externalId ต่อวันหรือต่อออเดอร์  
4. ใช้คู่กับใบกำกับ: ขายจาก I7 · ภาษีซื้อจาก I4 (อย่าให้ใบกำกับไปล้างยอดขาย — มีใน I5 แล้ว)  

**เสร็จเมื่อ**

- [ ] Σ ยอดขาย Shopee จากไฟล์ = ช่องทาง Shopee ในแท็บเดือนหลัง apply  

---

## I8 — ใบกำกับ Grab / LINE MAN + ZIP

**ทำ**

1. อะแดปเตอร์ใบกำกับ Grab (PDF) เมื่อมีตัวอย่างจริง — เลขที่ + gpVat  
2. ใบเสร็จค่าบริการ / ใบกำกับ LM ถ้าร้านใช้แยกจากรายงานเดือน  
3. อัปโหลด **ZIP** หลาย PDF (Shopee/Grab) ในครั้งเดียว — แตกในเบราว์เซอร์แล้ว parse ทีละไฟล์  
4. แสดงสรุปก่อน commit: สำเร็จ N · ข้ามซ้ำ M · พัง K  

**เสร็จเมื่อ**

- [ ] โยน ZIP ใบกำกับทั้งเดือน → ได้แถวครบโดยไม่เลือกไฟล์ทีละใบ  

---

## I9 — ปลด apply · ทะเบียนใบกำกับ · กันทับผิด

**ทำ**

1. **ยกเลิกใช้เข้าเดือน** ต่อแถวหรือทั้งชุด → `draft` อีกครั้ง · ตัวเลือกคืนค่าเดือนหรือไม่  
2. ทะเบียนใบกำกับในเดือน: ค้นหาเลขที่ · เปิดไฟล์ · รวม gpVat ต่อช่องทาง  
3. Confirm apply ชัดขึ้น: แสดงช่องทางที่จะ**ทับ** vs **ไม่แตะ**  
4. กัน apply ตอน `filed` (มีแล้ว) + กันทับยอดขายด้วยแถวที่ gross=0 (มีแนวแล้ว · ตรวจซ้ำ)  
5. (ทางเลือก) audit log สั้นๆ ว่าใคร apply เดือนไหน  

**เสร็จเมื่อ**

- [ ] ใส่ผิดแล้วปลด/ใส่ใหม่ได้โดยไม่ต้องลบเดือนทั้งก้อน  
- [ ] หาเลขใบกำกับในแท็บนำเข้าได้  

---

## I10 — ครบวงจรเดือน + เก็บกวาด

**ทำ**

1. คู่มือสั้นใน UI: ลำดับไฟล์ต่อช่องทาง (LM → Grab → Shopee ขาย → ใบกำกับ)  
2. หลัง apply สำเร็จ — ลิงก์/เตือนให้ไปแท็บเดือนตรวจสุทธิ  
3. (ทางเลือก) แบนเนอร์สุขภาพอะแดปเตอร์เมื่อ parse พังซ้ำ  
4. ตัดสินใจ M5: ถอด UI เมล/daily เก่าที่ไม่ใช้แล้ว ([`vat-phases-next.md`](./vat-phases-next.md))  
5. อัปเดตเช็คลิสต์เป็น「ผ่านเดือนแรก」แล้วปิด I6–I10  

**เสร็จเมื่อ (นิยามครบ)**

- [ ] เจ้าของทำครบหนึ่งเดือนปฏิทินด้วยไฟล์อย่างเดียว (คีย์มือเหลือแค่เคสพิเศษ)  
- [ ] เอกสารเฟสนี้และเช็คลิสต์ติ๊กครบ  
- [ ] ไม่พึ่ง Google Drive / แท็บเมลเก่า

## I0 รายละเอียดสัญญาตาราง (อ้างอิง)

### ชนิดแถว

| kind | ความหมาย |
|------|----------|
| `sales` | ยอดขาย ± คชจ. ± ยอดโอน |
| `transfer` | ยอดโอนอย่างเดียว |
| `tax_invoice` | ใบกำกับ · **invoiceNo** + gpVat |

### คีย์ไม่ซ้ำ

1. `channel + externalId`  
2. `channel + invoiceNo`  
3. `dateKey + channel + rowKind`  

### Storage

```
vat-imports/{YYYY}/{MM}/{channel}/{uploadId}-{safeFileName}
```

### Firestore

`vatImportRows/{id}` — ตามที่ ship ใน I1–I5
