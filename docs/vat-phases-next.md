## M0 — ตกลงรอบ + สูตร

**ทำแล้วในโค้ด**

1. รอบตัด: `00:00 น.` Asia/Bangkok · default วันที่ 1  
   - เช่น `00:00 น. 1/7/2569 → 23:59 น. 31/7/2569`  
   - (= ถึงก่อน `00:00 น. 1/8/2569` ไม่รวม)
2. สูตร: ภาษีขาย = ยอด × 7/107 · ภาษีซื้อ = GP + วัตถุดิบ · play-safe ปัดลง/claim
3. แยกส่วน: **เดลิเวอรี่** / **หน้าร้าน** (เรทคนละชุดได้)
4. Firestore: `vatMonthlyReturns/{YYYY-MM}` · `meta/vatMonthlySettings`

**เช็คก่อนไป M4**

- [ ] เจ้าของยืนยันวันเริ่มรอบ = 1 (หรือกำหนดอื่น)
- [ ] ยืนยันว่ายอดแอป/หน้าร้านนับตามรอบนี้

## M1 — กรอกเดือน

**ทำแล้ว**

- แท็บ **เดือน**: ยอดขายรวม · GP (ประมาณหรือคีย์บิล) · VAT วัตถุดิบ
- สรุป: ภาษีขาย / ภาษีซื้อ / สุทธิ ต่อส่วน + รวม
- บันทึกร่าง / บันทึกยอด · ปลดล็อกหลังปิด

**เช็คใช้จริง**

- [ ] กรอกเดือนก่อนหน้าด้วยยอดจริงได้ใน < 5 นาที
- [ ] ตัวเลขสุทธิอ่านง่าย ไม่สับสนกับยอดโอนสุทธิ

---

## M2 — ตารางทดเรท

**ทำแล้ว**

- แท็บ **ตารางทด**: เรทส่ง / เรทร้าน · ทดตัวเลข
- วันเริ่มรอบ (1–28)
- บันทึกเป็นเรทเริ่มต้น · นำเรทไปใช้กับเดือนนี้

**เช็คใช้จริง**

- [ ] ปรับ `gpOfOutput` / `inputClaimFactor` ให้ใกล้บิล GP จริง (ยัง play-safe)
- [ ] เรทส่ง vs ร้าน ต่างกันเมื่อจำเป็น

---

## M3 — ปิด → P&L

**ทำแล้ว**

- แท็บ **ปิด P&L** + แผงบน `/pnl/`
- โหมดรายได้: ก่อน VAT (แนะนำ) / รวม VAT
- `status: filed` หลังปิด · ปลดล็อกได้

**เช็คใช้จริง**

- [ ] ปิดเดือนแล้วตัวเลขโผล่สรุปรายเดือนถูก
- [ ] ห้ามพนักงานเห็นหน้านี้ (owner-only)

---

## M4 — ใช้จริงเดือนแรก (คิวหลักถัดไป)

1. Deploy + เปิดบน `telltea-shop.web.app/vat-sales/`
2. เลือกเดือน · อ่านแบนเนอร์รอบตัดยอดให้ชัวร์
3. ใส่ยอดส่ง (ทุกแอปรวม) + ยอดหน้าร้าน
4. ใส่ภาษีซื้อจากบิล GP สรุปเดือน (หรือใช้ประมาณแล้วปรับ)
5. ใส่ภาษีซื้อจากบิลวัตถุดิบ
6. ดูสุทธิ · ปรับตารางทดถ้าจ่ายเกิน/ต่ำผิดหู
7. ปิดเดือน → P&L

**เกณฑ์ผ่าน**

- [ ] ยื่นภาษีขายครบตามยอดจริง
- [ ] ภาษีซื้อไม่เกินบิลจริง (play-safe)
- [ ] ใช้เวลาปิดเดือนสั้นลงชัด vs ของเดิมรายวัน
