# โครงระยะยาว — ยอดเดลิเวอรี่ VAT

> อัปเดต: 2026-08-01 · **ยังไม่แกะตัวเลขเข้างบ** จนกว่าชั้นศึกษาจะนิ่ง  
> หน้า: `/vat-sales/` (งบเดือน) · `/vat-sales/sources/` (ที่มา)  
> AI อ่านแคตตาล็อกผ่าน `vatMailAgentDump` (token owner) — ไม่ใช้ Gmail secret

---

## 0) หลักที่ไม่เปลี่ยน

1. **หน่วยบัญชี = เดือน** — ตารางยอดเดลิเวอรี่ใน VAT เดือนคือปลายทางเดียว  
2. **หน้าที่มา ≠ งบ** — ศึกษา / คัด / ม้วน ที่ `/vat-sales/sources/` ก่อน แล้วค่อยผสาน  
3. **คอลัมน์คงที่ 4 ช่อง** ต่อช่องทาง (Grab / LINE MAN / Shopee):

| คอลัมน์ | ความหมาย |
|---------|----------|
| ยอดขายแอพ | ยอดที่แพลตฟอร์มรายงาน (รวม VAT) → ฐานภาษีขาย |
| ยอดโอน | เงินเข้าบัญชีหลังหัก GP |
| คชจ.GP | ค่าบริการ **ไม่รวม VAT** |
| VAT-ซื้อ | แวทจากบิลค่า GP |

4. **อย่าลงงบรายวัน** เป็นค่าเริ่ม — รายวันเป็นวัตถุดิบของ Grab (ม้วน) หรือ audit ภายหลัง  
5. **AI ช่วยจูน ไม่เขียนงบเอง** จนกว่า owner ยืนยันผสาน

```
Gmail / ไฟล์
    ↓ ซิงก์ + จัดช่องทาง (From ก่อน)
platformEmailReports  (+ แท็กศึกษา)
    ↓ ชั้นศึกษา (ยังไม่ใช่ตัวเลขงบ)
ข้อเสนอรายเดือน / แคตตาล็อก AI
    ↓ owner ยืนยันผสาน
vatMonthlyReturns.delivery  ← ยอดเดลิเวอรี่ใน VAT เดือน
```

## 1) ชั้นข้อมูล (layers)

| ชั้น | ที่เก็บ | บทบาท |
|------|---------|--------|
| **L0 วัตถุดิบ** | Gmail · PDF/Excel แนบ · อัปโหลดมือ | ของจริงจากแพลตฟอร์ม |
| **L1 แคตตาล็อก** | `platformEmailReports` | แถวเมล: ช่องทาง · ช่วง · ชนิดไฟล์ · แท็ก · ยังไม่ใช่ยอดงบ |
| **L2 ศึกษา** | แท็ก + `meta/vatMailStudyNotes` + Agent Dump API | คน+AI จัดกลุ่ม / ข้ามขยะ / เลือกแหล่งต่อเดือน |
| **L3 ข้อเสนอเดือน** | (ยังไม่สร้าง — เฟสถัดไป) เช่น `vatDeliveryMonthProposals/{yyyy-mm}` | ยอดที่ AI/อะแดปเตอร์เสนอ ต่อช่อง · ยังไม่ทับงบ |
| **L4 งบ** | `vatMonthlyReturns/{yyyy-mm}` | ยอดที่ owner รับแล้ว · ใช้คิดกำไร+VAT |

กฎ: **L1/L2 เขียนได้เสรีตอนจูน · L4 เขียนเฉพาะตอนผสานที่ยืนยัน**

## 2) โมเดลต่อช่องทาง (ระยะยาว)

### Grab
- **วัตถุดิบหลัก:** เมล/ไฟล์**รายวัน** (PDF สรุปยอดขาย)  
- **ข้าม:** Receipt/Tax Invoice รายออเดอร์ · แจ้งเตือนบัญชี  
- **ทางเข้า L4:** ม้วนรวมทั้งเดือน → 4 คอลัมน์เดือนเดียว  
- **ไม่** ใส่แถวรายวันลงงบ

### LINE MAN
- **เป้าหมาย:** รายงาน**สรุปเดือน** (PDF) ถ้ามี  
- **ช่วงศึกษา:** เมลรายวัน 2 สาย — `ยอดขายรายวัน` + `ยอดโอนออก` — ใช้เทียบ/สำรอง ไม่บังคับเป็นงบ  
- **ข้าม:** รีเซ็ตรหัส · ยืนยันอีเมล · โปรโม  
- **ทางเข้า L4:** ยอดรวมเดือนจากสรุปเดือน (หรือม้วนรายวันเมื่อตกลงแล้ว)

### ShopeeFood
- **เป้าหมาย:** ไฟล์**สรุปเดือน** (Excel/รายงาน)  
- **ช่วงศึกษา:** รายงานโอนเงินรายวัน / settlement — คนละชุดกับใบกำกับ commission  
- **VAT-ซื้อ:** จากใบกำกับค่า GP คนละ pipeline กับยอดขายแอพ  
- **ทางเข้า L4:** ยอดรวมเดือน + GP/VAT จากชุดที่ถูก

## 3) แท็กศึกษา (ภาษากลาง คน↔AI)

ใช้บนแถว L1 — **ไม่ผสานงบ**

| แท็ก | ความหมาย |
|------|----------|
| `grab-รายวัน` | วัตถุดิบม้วนเดือน Grab |
| `lm-สรุปเดือน` / `lm-รายวัน-ขาย` / `lm-รายวัน-โอน` | แยกชนิด LM |
| `sf-สรุปเดือน` / `sf-โอนรายวัน` | แยกชนิด Shopee |
| `excel` / `pdf` / `csv` | ชนิดไฟล์ |
| `รอแกะ` | อยู่ในคิวศึกษา |
| `ข้าม` | ขยะ / ใบกำกับรายออเดอร์ / ไม่ใช่ยอดเดือน |
| `ใช้ม้วนเดือน` | เลือกเข้ารอบม้วน (ยังไม่ใช่ L4) |

เฟสหลังจูน: แท็ก `พร้อมผสาน` เฉพาะเมื่อข้อเสนอเดือน (L3) พร้อมให้ owner กดผสาน

## 4) บทบาทคน / AI / ระบบ

| ใคร | ทำ | ไม่ทำ |
|-----|----|--------|
| **Owner** | เชื่อม Gmail · ซิงก์ · ยืนยันผสาน · แก้มือถ้าต้อง | ไม่ต้องอ่าน raw ทั้งกล่อง |
| **ระบบ** | จัดช่องทางจาก From · ซิงก์ · เก็บ PDF · ผสานเมื่อสั่ง | ไม่เดายอดลง L4 เอง |
| **AI (cloud)** | อ่าน Dump API · จัดกลุ่ม · เสนอแท็ก/ข้อเสนอเดือน · ร่างอะแดปเตอร์ | ไม่ถือ refresh token Gmail · ไม่เขียน L4 โดยไม่ยืนยัน |

ทางเข้า AI คงที่: `vatMailAgentDump` + เอกสารใน `docs/`  
ทางเลือกสำรอง: `#vat-mail-study-notes` · workflow dump

## 5) เฟสระยะยาว (ลำดับที่ล็อก)

| เฟส | ชื่อ | งานหลัก | เกณฑ์จบ | สถานะ |
|-----|------|---------|---------|--------|
| **D0** | โครงหน้า + ล้างของเก่า | VAT เดือน / ที่มา · ล้างยอดค้าง · คอลัมน์ 4 ช่อง | งบว่างหรือมือเท่านั้น | ✅ |
| **D1** | แคตตาล็อกเมล | Gmail sync · From→ช่องทาง · แท็ก · Agent API | AI อ่านแคตตาล็อกได้ · ช่องทางถูก | ✅ |
| **D2** | ชั้นศึกษา (ไม่แกะงบ) | แท็กขยะ · แยกชนิดเมลต่อช่อง · อัปเดตบันทึก AI · ปุ่ม/ออโต้「จูนศึกษา D2」 | ทุกแถวมีแท็กหรือข้าม · mismatch≈0 | ✅ |
| **D3** | ข้อเสนอเดือน (L3) | `vatDeliveryMonthProposals/{yyyy-mm}` · จัดกลุ่มเมลต่อช่อง/กลยุทธ์ · **ยอดยังว่าง** · ยังไม่ทับ L4 | owner เห็นโครงเดือนแยกจากงบ | ✅ |
| **D4** | เติมยอดใน L3 | parse เมล/PDF ข้อความ → ม้วนเข้าข้อเสนอ · **ยังไม่ทับ L4** | ข้อเสนอมียอดขาย/โอน/GP ต่อช่อง | 🔄 |
| **D5** | ผสานเข้างบ (L4) | ปุ่มยืนยันบนหน้าที่มา → `vatMonthlyReturns` | audit ได้ว่าเดือนนี้มาจากข้อเสนอไหน | ⬜ |
| **D6** | VAT-ซื้อ / ใบกำกับ GP | pipeline คนละชุดจากยอดขาย | คอลัมน์ VAT-ซื้อ ครบโดยไม่ปนยอดขาย | ⬜ |
| **D7** | กันเพี้ยนระยะยาว | health เมล · drift แม่แบบ · แจ้งเตือนขาดวัน | รู้เมื่อแพลตฟอร์มเปลี่ยนฟอร์แมต | ⬜ |

**หยุดที่ D2 จนกว่าจะตกลง D3** — ห้ามกระโดดไปแกะตัวเลขลง L4

## 6) สิ่งที่ทำตอนนี้ (คิวสั้นของ D4)

1. Owner: `/vat-sales/sources/` → **เติมยอดจากเมล (D4)**  
2. AI: อ่าน Dump `proposals` — ตรวจยอดต่อเดือน/ช่อง · ช่องที่ parse ไม่ผ่าน (มัก PDF ยังไม่ถอดข้อความ)  
3. ยัง**ไม่**กดผสานเข้างบ (D5) จนกว่าตัวเลข L3 ดูโอเค  
4. ถ้า Grab ยอดว่าง: ซิงก์เมลใหม่ให้ดึง PDF ข้อความ หรือเติมมือในงบทีหลัง
