# nPos — เฟสแก้ friction หน้างาน (หลังติดตั้ง)

อัปเดต: **แผน** (ยังไม่ ship โค้ด) · อ้างอิง pain จาก flow ติดตั้ง → ขาย → ปิดกะ  

หลัก: **นโยบายที่ล็อกแล้วไม่เปิดเฟสแก้** · เฟสนี้โฟกัสข้อที่งงตอนใช้ / สถานะค้าง / ข้อความไม่ชัด  
คนเทสเคาน์เตอร์ (E/F/Z field) ทำคู่ขนานได้ทุกเฟส

---

## นอกเฟส (ไม่แก้พฤติกรรม)

| ข้อ | เหตุ |
|-----|------|
| PromptPay / พิมพ์ซ้ำ / X·Z ไม่เปิดลิ้นชัก | `CashDrawerPolicy` ตั้งใจ |
| ทอนรอบถัดไป > นับได้ → บล็อก | กันเงินหาย |
| บิลค้าง outbox → ปิด Z ไม่ได้ | กันยอดรอบเพี้ยน |
| ปิดกะจากเว็บ | นอกสcope · Z บน native เท่านั้น |
| อัปเดตไม่ silent | ต้องกดยืนยัน Android |

---

## F0 — คนเทสเคาน์เตอร์ (ไม่เขียนโค้ด)

ยืนยันของที่ ship แล้วก่อนเริ่มเฟสแก้

- [ ] F0.1 เคลมรหัส → เปิดกะ → ขายสด (ใบเสร็จ + ลิ้นชัก)
- [ ] F0.2 PromptPay → ใบเสร็จ · ลิ้นชักไม่เปิด
- [ ] F0.3 พิมพ์ซ้ำ / X / Z → ลิ้นชักไม่เปิด
- [ ] F0.4 แก้ชื่อร้านหลังบ้าน → รีโหลดแอป → หัวบิลใหม่
- [ ] F0.5 เครื่องไม่เคลม / AVD → ส่งบิลไม่ได้

**จบเมื่อ:** มีบันทึกหน้างาน ผ่าน/ไม่ผ่าน แต่ละข้อ

---

## F1 — เคลม vs ขาย: ข้อความให้ชัด

**ปัญหา:** ดูเมนูได้แต่เปิดกะ/ขายไม่ได้ · พนักงานไม่รู้ว่าต้องเคลม  
**เป้า:** หน้าเข้างาน / ขาย บอกชัดว่า “เครื่องยังไม่เคลม · กรอกรหัสร้าน” · ปุ่มเปิดกะ/จ่าย disable หรือกดแล้วได้ข้อความภาษาคน

### งาน
- [ ] F1.1 Hub / เข้างาน: แบนเนอร์สถานะเคลม (ยังไม่เคลม · ถูกถอน · เครื่องถูกบล็อก)
- [ ] F1.2 เปิดกะตอนเกตเปิดแต่ยังไม่เคลม → dialog ชี้ไปช่องรหัส (ไม่โชว์ error ดิบจาก CF)
- [ ] F1.3 ขาย/flush `device_not_allowed` → toast ไทยสั้น + ปุ่มไปหน้าเคลม
- [ ] F1.4 Gate สคริปต์ assert ข้อความ/แบนเนอร์มีใน native

**ไม่ทำใน F1:** exclusive เครื่องเดียว (ไป F4)

---

## F2 — ลิ้นชักตอนปิดพิมพ์อัตโนมัติ

**ปัญหา:** ขายสดแต่ปิด `autoPrintReceipt` → ไม่พิมพ์และ**ไม่**เตะลิ้นชัก  
**เป้า:** เงินสดยังเปิดลิ้นชักได้แม้ไม่พิมพ์ใบเสร็จ (พิมพ์กับลิ้นชักแยกกัน)

### งาน
- [ ] F2.1 ตัดสินผลิตภัณฑ์: ขายสด → kick หลังขายสำเร็จ (ไม่ผูกพิมพ์) **หรือ** บังคับพิมพ์ตอนสด
- [ ] F2.2 ปรับ `SaleSync` / `CashDrawerPolicy` ตาม F2.1
- [ ] F2.3 อัปเดต `npos-doc-drawer-polish-checklist` + gate
- [ ] F2.4 คนเทส: ปิด autoPrint → ขายสด → ลิ้นชักเปิด · ไม่มีกระดาษ

**ค่าเริ่มต้นที่แนะนำ:** kick หลังขายสดสำเร็จ แม้ไม่พิมพ์ (ลิ้นชัก = เงิน · ใบเสร็จ = กระดาษ)

---

## F3 — เปิดกะออฟไลน์ × เกตเคลม

**ปัญหา:** เน็ตหลุดอาจเปิดกะในเครื่องได้ แล้วซิงก์ทีหลังติด `device_not_*` ค้างคิว  
**เป้า:** สถานะชัด · ไม่เปิดกะหลอกเมื่อเกตต้องการเคลมแต่ยังไม่ผ่าน · หรือคิวมีป้ายเหตุผลภาษาคน

### งาน
- [ ] F3.1 ถ้า `storeClaimRequired` และยังไม่เคลม → ห้ามเปิดกะออฟไลน์ (บังคับเคลมตอนมีเน็ต)
- [ ] F3.2 เปิดกะออฟไลน์ได้เฉพาะเครื่องที่เคลมแล้ว + มี session local
- [ ] F3.3 ป้ายคิวซิงก์แยก `device_not_allowed` / เน็ตหลุด / อื่นๆ
- [ ] F3.4 Gate + คนเทส: ปิด Wi‑Fi ก่อนเคลม → เปิดกะไม่ได้; เคลมแล้วปิด Wi‑Fi → เปิดกะ local ได้

---

## F4 — (ทางเลือก) เครื่องเดียวต่อร้าน

**ปัญหา:** รหัสร้านเดียวกันเคลมได้หลายแท็บเล็ต  
**เป้า:** โหมด “เคาน์เตอร์หลักเครื่องเดียว” ถ้าร้านต้องการ

### งาน
- [ ] F4.0 ตัดสิน: multi-device คงไว้เป็นค่าเริ่มต้น **หรือ** เพิ่มสวิตช์หลังบ้าน
- [ ] F4.1 ถ้าเปิด exclusive: เคลมเครื่องใหม่ → ถอนเครื่องเก่าอัตโนมัติ + แจ้งบนเครื่องเก่า
- [ ] F4.2 แผง manage แสดง “เครื่องที่เคลมอยู่” ชัด
- [ ] F4.3 Gate + คนเทสสองแท็บเล็ต

**ลำดับ:** ทำหลัง F1–F3 ถ้าหน้าร้านร้องจริงเท่านั้น

---

## F5 — สอนสั้นในแอป (เบา)

หลัง F1–F2 เพื่อลดงงนโยบายที่ไม่แก้

- [ ] F5.1 หน้าตั้งค่าปริ้น: บรรทัดเดียว “ลิ้นชักเปิดหลังขายเงินสด …”
- [ ] F5.2 หลังปิดกะครั้งแรก (หรือตั้งค่า): tip สั้น X ≠ ปิดกะ · Z = นับเงินก่อน

---

## ลำดับทำ + ความเสี่ยง

```
F0 คนเทส ──┬──► F1 ข้อความเคลม     (UX · เสี่ยงต่ำ)
            ├──► F2 ลิ้นชัก≠พิมพ์   (พฤติกรรมขาย · ต้องตัดสินก่อนโค้ด)
            └──► F3 กะออฟไลน์×เคลม  (session/outbox · ระวังรีเกรสชันเปิดกะ)
                    └──► F4 exclusive (ทางเลือก)
F5 tip ในแอป หลัง F1/F2
```

| เฟส | กระทบ | ความเสี่ยง |
|-----|--------|------------|
| F0 | ไม่มี | — |
| F1 | UI เข้างาน/ขาย | ต่ำ |
| F2 | `SaleSync` + policy | กลาง — คนเคยชินแบบผูกพิมพ์ |
| F3 | เปิดกะ + คิว | กลาง–สูง — อย่าบล็อกกะเครื่องที่เคลมแล้วตอนเน็ตหลุด |
| F4 | `nposClaimDevice` + manage | สูงถ้าร้านใช้ 2 เครื่องจริง |
| F5 | copy ตั้งค่า | ต่ำ |
