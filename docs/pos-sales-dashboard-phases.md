# แดชบอร์ดหน้าขาย `/pos-sales/` — แผนเฟส + แมปข้อมูล

อัปเดต: 2026-08-02  
อ้างอิง UI: กล่องแบบ FoodStory (ยอดขายสุทธิ · บิล · กราฟรายวัน/ชั่วโมง/วันในสัปดาห์ · สินค้า · สต็อก · โปร · ลูกค้า · โต๊ะ · พนักงาน)  
แหล่งข้อมูลหลัก: `posSales` · `posSessions` · `menuItems`/`menuCategories` · `meta/posMenuRank` · `stock`/`stockMovements` · `dailySales` (VAT)

---

## เป้าหมาย UX

วางแดชบอร์ดไว้ **ด้านบนหน้าขาย** (`/pos-sales/`) แยกเป็น **แท็บย่อย** + **ตัวเลือกช่วงวันที่** (calendar range)

### โครงแท็บ (เสนอ)

| แท็บ | URL | เนื้อหา |
|------|-----|---------|
| **แดชบอร์ด** | `/pos-sales/?tab=dashboard` (default ใหม่) | กล่องสรุป + กราฟ (เฟสตามด้านล่าง) |
| **รอบขาย** | `/pos-sales/?tab=sessions` | ตารางรอบ + บิล + พิมพ์ X/Z (ของเดิมย้ายมา) |
| **จัดการ** | `/pos-sales/?tab=manage` | เครื่อง · ops · ตั้งค่าร้าน (คงเดิม) |

ตัวกรองร่วมทุกแท็บแดชบอร์ด: **ช่วงวันที่** `DD/MM/YYYY – DD/MM/YYYY` (Bangkok local)  
ค่าเริ่มต้น: เดือนปัจจุบัน หรือ วันนี้–วันนี้ (เลือกตอน implement)

> หมายเหตุนโยบายเดิม (`npos-sales-history-checklist`): custom date range เคยอยู่นอกสcope ประวัติบิล — **รอบนี้เปิดเฉพาะแท็บแดชบอร์ด** ไม่บังคับเปิดบนรายการบิลทันที

## สถานะข้อมูลที่มี vs กล่องในภาพ

สัญลักษณ์: ✅ มีครบ · 🟡 ปรับชื่อ/รวมช่องทางให้เข้าข้อมูลเรา · 🔴 ไม่มีข้อมูล — ซ่อนหรือทำทีหลังหลังเก็บฟิลด์ใหม่

### แถว 1 — สรุปยอด / บิล / ยกเลิก

#### กล่อง A · ยอดขายสุทธิ

| ส่วนในกล่อง | สถานะ | แมปข้อมูลเรา |
|-------------|--------|----------------|
| ยอดขายสุทธิ (ตัวใหญ่) | ✅ | `Σ posSales.total` ที่ `status=completed` ในช่วงวันที่ |
| แถบชำระเงิน | 🟡 | มี 3 ช่องทาง: `cash` / `promptpay` / `transfer` — **ไม่ใช่** แค่ “เงินสด vs อื่นๆ” → แสดง 3 ท่อน หรือ เงินสด vs โอน+PP |
| จำนวนเงินต่อช่องทาง | ✅ | รวม `total` ต่อ `paymentMethod` (+ % ) |
| ยอดขาย (ก่อนลด) | ✅ | `Σ subtotal` |
| ลดราคา | 🟡 | มีแค่ **ลดท้ายบิล** `discountBaht` — ไม่มีลดรายบรรทัดแยก → รวมเป็น “ส่วนลด” แถวเดียว (หรือแสดง 0 ที่ลดรายการ + ใส่ค่าที่ลดท้ายบิล) |
| ลดท้ายบิล | ✅ | `Σ discountBaht` |
| แลกแต้ม (loyalty) | ✅ P3 | แยกส่วนลดมือ / แลกแต้ม + กล่องแต้มได้/ตัด — ดู [members-round-phases.md](./members-round-phases.md) P3 |
| ค่าบริการ | 🔴 | ไม่เก็บบนบิล → **ซ่อน** หรือแสดง `0` พร้อมข้อความ “ยังไม่ใช้ในระบบ” |
| ค่าจัดส่ง | 🔴 | ไม่เก็บบนบิล POS → **ซ่อน** (ยอด delivery อยู่ที่ `dailySales` คนละชั้น) |
| ภาษี 7% | 🔴 | ไม่เก็บบนบิล POS (VAT รวมอยู่หน้า `/vat-sales/`) → **ซ่อนจากกล่องนี้** |
| ยอดปัดเศษ | 🔴 | ไม่มี → **ซ่อน** |
| รวมสุทธิ | ✅ | = ยอดขายสุทธิ |

**ปรับ UI ให้เข้าของเรา:** รายการขวาเหลือ  
`ยอดขาย` · `ส่วนลด` · `รวมสุทธิ` (+ optional info ว่าไม่รวม VAT/delivery)

#### กล่อง B · บิลที่ปิดไปแล้ว

| ส่วนในกล่อง | สถานะ | แมปข้อมูลเรา |
|-------------|--------|----------------|
| จำนวนบิลทั้งหมด | ✅ | นับ `posSales` ที่ completed |
| โดนัทแยกประเภท | 🟡 | **ไม่มี** dine-in / takeaway / delivery บนบิล POS |
| ทานที่ร้าน / ซื้อกลับ / จัดส่ง | 🔴→🟡 | ทางเลือกปรับ: (1) แยกตาม **ชำระเงิน** แทนประเภทออเดอร์ หรือ (2) รวม **หน้าร้าน (`posSales`) vs เดลิเวอรี (`dailySales.delivery`)** คนละแหล่ง — ไม่ผสมในโดนัทเดียวโดยไม่บอกที่มา |
| ปุ่มดูเพิ่มเติม | ✅ | ลิงก์ไปแท็บรอบขาย / รายการบิล |

**มติเสนอ:** โดนัท = **ช่องทางชำระ** (สด / PP / โอน) หรือซ่อนโดนัทประเภทออเดอร์จนกว่าจะเก็บ `orderType` — **ไม่หลอกว่าเป็น dine-in**

#### กล่อง C · บิลที่ยกเลิก

| ส่วนในกล่อง | สถานะ | แมปข้อมูลเรา |
|-------------|--------|----------------|
| คืนเงิน (refund) | 🔴 | ไม่มี refund — มีแค่ void |
| ทำลาย (void) | ✅ | `status=voided` → นับบิล + `Σ total` |
| จำนวนบิล | ✅ | `voidedCount` |

**ปรับ UI:** กล่องเดียว “บิลทำลาย” (จำนวน + ยอด) — **ไม่แสดงคอลัมน์คืนเงิน** จนกว่าจะมีฟีเจอร์ refund

### เฟส 6 — ขยายข้อมูลในอนาคต (นอกสcope ตอนนี้)

ทำเมื่อเก็บฟิลด์/ฟีเจอร์ใหม่ที่เคาน์เตอร์:

| ความต้องการ UI | ต้องมีก่อน |
|----------------|------------|
| Dine-in / takeaway / delivery บนบิล | `orderType` (หรือ channel) ตอนปิดบิล |
| คืนเงินแยกจากทำลาย | workflow refund |
| ค่าบริการ · ภาษีบนบิล · ปัดเศษ | ฟิลด์บน `posSales` + UI เคาน์เตอร์ |
| โปรโมชั่นจริง | รหัสโปร / แคมเปญ |
| ลูกค้าจริง | CRM / เบอร์บนบิล |
| โต๊ะ | โมเดลโต๊ะ + เปิดบิลผูกโต๊ะ |
| เวลาเปิดบิล | timestamp ตอนเปิดออเดอร์ (ตอนนี้ปิดจบในครั้งเดียว) |
| รวม delivery ในโดนัทเดียวกับ POS | กติคารวม `dailySales` ให้ชัด + ไม่ double-count |

## ลำดับลงมือแนะนำ

```
เฟส 0 (แท็บ + วันที่ + query)
  → เฟส 1 (การ์ดสรุปบน)
  → เฟส 2 (กราฟ)
  → เฟส 3 (สินค้า)
  → เฟส 4 (ส่วนลด · สถิติบิล · กิจกรรม)
  → เฟส 5 (สต็อก) [ออปชัน]
```

เฟส 0 เป็น blocker ของทุกกราฟ/สรุปรายเดือน  
เฟส 1 ให้คุณค่าทันทีแม้ยังไม่มีชาร์ต

## เกณฑ์ไม่ทำในรอบแรก

- ไม่ใส่ตัวเลขปลอมให้ครบกล่อง FoodStory
- ไม่เก็บฟิลด์ใหม่บนเคาน์เตอร์ในเฟส 0–4
- ไม่ผสมยอด VAT delivery เข้า “ยอดขายสุทธิ POS” โดยไม่ติดป้ายแหล่งที่มา
- ไม่ทำกล่องโต๊ะ
- ไม่บังคับ custom date range บนรายการบิลในแท็บรอบขายพร้อมกัน (ทำทีหลังได้)
