## 2. นโยบาย Sync (แนะนำที่ยอมรับแล้วในทิศ)

**หลัก:** Firestore + Cloud Functions เป็นความจริงเดียว · อย่าเก็บเมนูทั้งก้อนเป็น “ไฟล์ท้องถิ่นแก้ไขค้าง”

| ฝั่ง | พฤติกรรมที่ต้องการ |
|------|---------------------|
| **เขียนจาก nPos** | เรียก API/เขียน Firestore → รอผลสำเร็จ → `bumpMenuVersion` → อัปเดต UI ท้องถิ่นจากของที่ server ยืนยัน · ระหว่างรอโชว์「กำลังบันทึก…」และปุ่ม disable |
| **อ่านบน nPos (ขาย + จัดการ)** | หลังเขียนตัวเองหรือได้ `menuVersion` ใหม่จาก heartbeat → โหลด `nposMenuSnapshot` ใหม่ทั้งก้อน |
| **เขียนจากหลังร้าน** | ของเดิม `pos-menu*.ts` + `bumpMenuVersion` · **เพิ่ม** ให้หน้า `/menu/` ฟัง `meta/pos.menuVersion` (หรือ `onSnapshot` ชุดเมนู) แล้วรีเฟรชลิสต์โดยไม่ต้องออกเข้าใหม่ |
| **ขัดแย้ง** | เครื่องเดียวตอนนี้ · ถ้า sync ไม่สำเร็จ → **ไม่ถือว่าเปลี่ยน** (revert UI / เก็บค่าเดิม) · toast ชัด「ยังไม่บันทึก ลองใหม่」 |
| **ออฟไลน์** | **ไม่เปิดแก้เมนูออฟไลน์** ในเฟสนี้ (ขายอาจมีของเดิมในแคช — จัดการเมนูต้องออนไลน์) |

ไม่บังคับ “ล็อกสองฝั่งรอกัน” แบบ two-phase commit — ใช้ **write-through + version bump + refresh** ซึ่งพอสำหรับเครื่องเดียวและพนักงานหน้างาน

## 6. แผน UI Native (กันเอ๋อ)

| หลักการ | รายละเอียด |
|---------|------------|
| โครงข้อมูล | แท็บเดียวกับ BOH (ตัดโปรโม) |
| รายการยาว | **ตาราง/แถว** ชื่อ · ราคา · สถานะ · ปุ่มสั้น — ไม่ใช้การ์ดหนาแน่น |
| ฟอร์ม | สกรอลล์แนวตั้ง · สัมผัสใหญ่ตาม `npos-friendly-ui` |
| ทางเลือก | ปุ่ม `NposUi.primary/secondary` เต็มแถว — ไม่ใช้ list dialog บาง |
| กดค้างขาย | แผงล่างหรือ dialog ใหญ่ 2–3 ปุ่มเท่านั้น |
| รูป | พื้นที่พรีวิวคงที่ · ไม่ดันฟอร์มเพี้ยนตอนโหลด |
| แนวนอนแท็บเล็ต | แท็บบนหรือซ้ายสั้นๆ · เนื้อหาไม่บีบต่ำกว่า touch min |
| ข้อความ | ไทยสั้น พนักงานอ่านรู้เรื่อง: ของหมด / กำลังบันทึก / บันทึกแล้ว / ยังไม่บันทึก |

ถ้าฟีเจอร์ BOH ไหนแปลงแล้ว UI พังบน native → **ตัดความซับซ้อนของฟีเจอร์นั้นบน nPos ชั่วคราว** เหลือตาราง+ฟอร์มหลัก แล้วเปิดทีหลัง — อย่าฝืนเว็บ 1:1 จนใช้งานไม่ได้

- [ ] A3 เข้าหน้าเมนูเห็นแท็บ 3: เมนูอาหาร · กลุ่มตัวเลือก · ตั้งราคา · **ไม่มี**โปรโม
- [ ] A4 รายการที่โชว์ตรงกับของในร้าน (เทียบหลังร้าน `/menu/`)
- [ ] A5 ไม่มีเน็ต / โหลดไม่ได้ → ข้อความชัด ไม่หน้าว่างเงียบ

### B — ของหมดจากกริดขาย (P2)

- [ ] B1 กดค้างเมนูที่ขายได้ → เห็นปุ่มปิดของหมด + แก้ไขเมนู (ไม่เด้ง confirm อย่างเดียวแบบเดิม)
- [ ] B2 กดปิดของหมด → มี「กำลังบันทึก」→ สำเร็จแล้วกริดเป็นของหมด · แตะสั้นสั่งไม่ได้
- [ ] B3 กดค้างรายการของหมด → เปิดขายอีกครั้งได้ · สั่งได้อีก
- [ ] B4 ตอนกำลังบันทึก กดซ้ำไม่ทำให้สถานะเพี้ยน
- [ ] B5 ปิดเน็ตแล้วกดปิดของหมด → แจ้งล้มเหลว · สถานะบนกริด**ไม่เปลี่ยน**
- [ ] B6 (ถ้ามีของในตะกร้า) ปิดของหมดแล้วแถวในตะกร้าถูกลบ/กันตามพฤติกรรมเดิมที่ตกลง

### C — ของหมดจากหน้าจัดการ + สองฝั่ง (P2+P5)

- [ ] C1 ในหน้าเมนู nPos สลับของหมดรายการหนึ่ง → กริดขายอัปตาม (เปิดขายค้างไว้คนละจอหรือสลับไปกลับ)
- [ ] C2 หลังร้าน `/menu/` เปิดค้าง → หลัง nPos ปิดของหมด รายการหลังร้านอัปเอง (หรือภายในไม่กี่วินาทีหลัง listener)
- [ ] C3 หลังร้านกดของหมด/เปิดขาย → กริด nPos อัปโดยไม่ต้องปิดแอป

### D — สร้าง/แก้เมนูและรูป (P3)

- [ ] D1 สร้างเมนูใหม่จาก nPos (ชื่อ · หมวด · ราคาหน้าร้าน · ราคาเดลิเวอรี่) → บันทึกสำเร็จ
- [ ] D2 กลับหน้าขาย หมวดนั้นเห็นเมนูใหม่หลัง sync · ราคาหน้าร้านถูก
- [ ] D3 ใส่รูป + ครอป → รูปขึ้นทั้งกริดขายและหลังร้าน
- [ ] D4 เปลี่ยนรูปทับ → รูปใหม่ขึ้น · ไม่ค้างรูปเก่า
- [ ] D5 อัปโหลดรูปล้มเหลว → เมนูไม่เสีย · แจ้งลองใหม่
- [ ] D6 กดค้าง「แก้ไข」จากกริด → เปิดฟอร์มรายการนั้น พร้อมข้อมูลเดิม
- [ ] D7 แก้ชื่อ/ราคา → บันทึก → ทั้งขายและหลังร้านตรงกัน
- [ ] D8 เก็บเข้าคลัง → ไม่โชว์บนกริดขาย · หลังร้านอยู่ในคลัง
- [ ] D9 เปิดคืนจากคลัง → ขายได้อีก
- [ ] D10 ลบถาวร (ถ้ารองรับ) → ต้องยืนยัน · หายทั้งสองฝั่ง
- [ ] D11 สำเนาเมนู → ได้รายการใหม่ แก้ชื่อได้

### E — หมวดและตัวเลือก (P4)

- [ ] E1 สร้างหมวดใหม่ → เรียงลำดับ → โผล่บนแถบหมวดหน้าขายตามลำดับ
- [ ] E2 แก้ชื่อหมวด → ทั้ง nPos ขายและหลังร้านตรง
- [ ] E3 สร้างกลุ่มตัวเลือก + ตัวเลือกย่อยราคาเพิ่ม (หน้าร้าน+เดลิเวอรี่)
- [ ] E4 ผูกกลุ่มกับเมนู → ตอนขายขึ้น picker ถูก · required บังคับครบ
- [ ] E5 ปิด choice หนึ่งตัว → ตอนขายไม่ให้เลือก (หรือโชว์ปิดตามพฤติกรรม BOH)
- [ ] E6 ตั้งราคาจากแท็บตาราง → ราคาในฟอร์มรายการและหน้าขายตรง

### F — ความทนทานหน้างาน (P5+P6)

- [ ] F1 ระหว่างบันทึกเมนู หน้าจอไม่ค้างตาย · มีสถานะโหลด
- [ ] F2 ออกจากฟอร์มกลางทางโดยไม่บันทึก → ของเดิมไม่เปลี่ยน
- [ ] F3 เปิดหน้าจัดการเมนูทั้งกะเช้า–บ่าย ไม่ memory บวมจนแอปช้าผิดปกติ (สังเกตการณ์)
- [ ] F4 Demo/เครื่องยังไม่ผูกโค้ดร้าน → แก้เมนูไม่ได้ มีข้อความรู้เรื่อง
- [ ] F5 พนักงานคนที่「ไม่เคยใช้หลังร้าน」ทำ B1–B3 และ D1–D3 ได้เองจากคำอธิบายสั้นๆ บนจอ

### G — ไม่ทำ / ต้องไม่มีใน nPos

- [ ] G1 ไม่มีแท็บโปรโมชั่นบน nPos
- [ ] G2 ไม่มีนำเข้า CSV
- [ ] G3 ไม่ถามรหัสพิเศษเพิ่มก่อนเข้าเมนู (เฟสนี้ทุกคนในกะเข้าได้)
- [ ] G4 กดค้างไม่มี「เก็บเข้าคลัง」หรือ「ลบ」 — ทำในฟอร์มเต็มเท่านั้น

## 8. เกณฑ์ปิดงานรวม (Definition of Done)

ชุดนี้ถือว่าเสร็จเมื่อ:

1. Hub「เมนู」ลำดับ 2 ใช้ได้เฉพาะตอนเปิดกะ  
2. CRUD เมนู/หมวด/กลุ่มตัวเลือก/ราคา(+เดลิเวอรี่)/รูป บน nPos เทียบหลังร้านในขอบเขตที่ระบุ  
3. กดค้างกริด = ปิด/เปิดของหมด + ทางเข้าแก้ไข  
4. แก้ฝั่งใดฝั่งหนึ่ง อีกฝั่งอัปเองโดยไม่ต้อง remount แอป (ตาม P5)  
5. ออฟไลน์/ล้มเหลวแล้วข้อมูลไม่เพี้ยนเงียบ  
6. เช็คลิสต์ข้อ 7 ผ่านครบโดยคนหน้างาน  
7. ไม่มีโปรโมบน nPos · ยังไม่ใส่ RBAC แยก

## 9. ลำดับ ship แนะนำ (เทคนิค)

```
P0 เอกสาร
P1 Hub + หน้าอ่านอย่างเดียว          ← ship ภายในได้ ลองทางเข้า
P2 ของหมดด่วน (กริด+สวิตช์ลิสต์)      ← ship เร็ว ได้คุณค่าหน้างานทันที
P3 CRUD รายการ+รูป                   ← ก้อนใหญ่
P4 หมวด+ตัวเลือก+ตารางราคา           ← ต่อจาก P3 API เขียน
P5 Listener สองทางแน่น
P6 เช็คหน้างานเต็มชุด → ปิดงาน
```

P2 แยก ship ก่อน P3 ได้และควรทำ — พนักงานได้ปุ่มปิดของหมดที่ดีขึ้นทันที ขณะที่ฟอร์มเต็มกำลังสร้าง
