# nPos → หลังร้าน: เก็บยอดขายอย่างไร (แผน)

อัปเดต: **1.14.38**  
เป้าหมาย: ยอดขายจากเคาน์เตอร์ไม่หาย · หลังร้านเห็นรอบ/เครื่อง/ยอดชัด · ไม่เก็บของที่ไม่จำเป็นจนช้า

---

## สิ่งที่เก็บอยู่แล้ว (อย่าทิ้ง)

| ที่ | เก็บอะไร | หมายเหตุ |
|-----|----------|----------|
| **`posSales`** | บิลเต็ม: เมนู+ออปชัน · ยอด · ส่วนลด · ชำระ · เงินทอน · sessionId · deviceId · สถานะ/void | แหล่งจริงของรายงาน |
| **`posSaleMutations`** | idempotency ของบิล | กันซ้ำตอนซิงก์ |
| **`posSessions`** | รอบเปิด/ปิด · saleCount · totalSales · ทอนเปิด · ปิดกะ blind (นับจริง / over-short / leave float) | บั๊มยอดตอนขาย · ปิดละเอียดตอน Z |
| **แท็บเล็ต outbox** | คิวยังไม่ซิงก์ | local-first — จนกว่า `nposCompleteSale` สำเร็จ |
| **ใบเสร็จ local** | พิมพ์ซ้ำ/void บนเครื่อง | เพดาน ~60 ใบบนเครื่อง (ของเก่าบนเครื่องทิ้งได้ถ้าซิงก์แล้ว) |

**อย่าลบ `posSales` / `posSessions` เป็นค่าเริ่ม** — รายงาน `/pos-sales` อ่านจากสองชุดนี้

---

## สิ่งที่ยังไม่ขึ้นหลังร้าน (ช่องว่าง)

1. **คิวค้าง / บิลยกเลิกก่อนซิงก์** — อยู่แค่เครื่อง · ถ้าถอนแอปหาย  
2. **ชื่อพนักงาน / ข้อความท้ายใบเสร็จ** — ตัดออกตอน POST · ไม่เข้า `posSales`  
3. **แยกสด / PromptPay บน session ขณะเปิด** — เซิร์ฟเวอร์อัปแค่ยอดรวมจนปิดกะ  
4. **ตารางเครื่อง (เดิม)** — มีแค่ seat/ออนไลน์ ไม่ผูกยอดรอบ → **1.14.38 เริ่มโชว์รอบ+ยอดจาก `posSessions` วันนี้**  
5. **รหัสร้านเต็ม** — เคยเก็บแค่ hash → **1.14.38 เก็บตัวเต็มใน `meta/posStoreClaimSecret` (เจ้าของเท่านั้น)**

## แนวที่ควรทำต่อ (ลำดับแนะนำ)

### P0 — ทำให้ของที่มีอยู่ “เห็นชัด” (ถูกทางแล้ว / ทำต่อได้ทันที)
- ตารางเครื่อง: รอบเปิด · ของใคร · ยอดรอบ (ทำแล้วใน 1.14.38)
- รายงานวัน: การ์ดรอบ + รายการบิล (มีแล้วที่ `/pos-sales`)
- เตะ ≠ ปิดกะ — รอบเดิม resume ได้ (มีแล้ว)

### P1 — อย่าให้ยอดค้างบนเครื่องหาย
- ส่ง **สรุป outbox** ขึ้น `posDevices` หรือ diagnose: `pendingCount` / `failedCount` / `oldestPendingAt`
- BO แถบเตือน: “เครื่องนี้มี N บิลยังไม่ซิงก์”
- (ถัดไป) เก็บ outbox สำรองบนเครื่องนานขึ้น หรือ Room — ไม่บังคับทันทีถ้า P1 เตือนชัด

### P2 — ทำให้รอบ “สด” บนหลังร้านขณะขาย
- ตอน `nposCompleteSale` อัป `cashTotal` / `promptpayTotal` บน session ด้วย (ไม่รอปิดกะ)
- หรือ derive จาก `posSales` ของ session นั้นใน UI (ไม่ต้องเขียนซ้ำถ้า query พอ)

### P3 — ฟิลด์ที่ควรเก็บเพิ่มเมื่อมี use-case จริง
| ฟิลด์ | ทำไม | เมื่อไหร่ |
|-------|------|----------|
| `staffName` / `staffId` | ตรวจผลงานกะ | เมื่อผูกพนักงานเคาน์เตอร์ |
| `channel` (takeaway ฯลฯ) | วิเคราะห์ช่องทาง | เมื่อเปิดหลายช่องจริง |
| `receiptFooterNote` snapshot | ตรวจใบเสร็จย้อนหลัง | ต่ำ — ถ้าพิมพ์ผิดบ่อย |
| `voidReason` มาตรฐาน | สรุปทำลาย | มีแล้วบางส่วน |

### ไม่ควรทำ
- เก็บใบเสร็จภาพ/ESC ดิบทุกบิลใน Firestore (แพง · ซ้ำกับ `posSales`)
- ให้เว็บปิดกะแทนแท็บเล็ต (นโยบาย S1–S3)
- ล้าง `posSales` อัตโนมัติตามวันโดยไม่มี archive

## สรุปสั้นสำหรับทีม

**แหล่งจริง = Firebase `posSales` + `posSessions`**  
แท็บเล็ต = คิวก่อนซิงก์ + พิมพ์  
หลังร้าน = อ่านคอลเลกชันนั้น + โชว์บนตารางเครื่อง/รายงาน  

ขั้นถัดไปที่คุ้มที่สุด: **สัญญาณบิลค้างซิงก์บนเครื่อง (P1)** แล้วค่อย **แยกสด/PP สดบนรอบ (P2)**
