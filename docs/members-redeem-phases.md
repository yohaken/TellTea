# ใช้แต้มที่เคาน์เตอร์ + ข้อมูลบนบิล / หลังร้าน / แดชบอร์ด — เฟส

อัปเดต: 2026-08-07  
อ้างอิง: [members-crm-phases.md](./members-crm-phases.md) · [members-receipt-qr-phases.md](./members-receipt-qr-phases.md) · [pos-sales-dashboard-phases.md](./pos-sales-dashboard-phases.md)  
**เช็กลิสต์ติ๊กทีละข้อ (ยาว):** [members-redeem-checklist.md](./members-redeem-checklist.md)

ไอเดียง่ายที่ล็อกแล้ว (พนักงานคีย์):

```text
ลูกค้าแจ้งเบอร์
  → พนักงานคีย์บนเครื่องตอนคิดเงิน
  → ระบบโชว์แต้มคงเหลือ
  → ระบบโชว์เงินที่แลกได้ (ตาม pointsPerBahtRedeem)
  → พนักงานยืนยันจำนวนแต้ม / เงินลด
  → ปิดบิล: หักแต้ม + ลดยอดสุทธิ + เก็บหลักฐานบนบิล
```

**ยังไม่ครบถ้าทำแค่ UI คีย์เบอร์** — ต้องมีสัญญาข้อมูลบนบิล · สลิป · หลังร้าน · แดชบอร์ด · ยกเลิกบิล ไม่งั้นยอด/แต้มเพี้ยนและไล่ตรวจไม่ได้

---

## หลักการรอบนี้

| ข้อ | ความหมาย |
|-----|----------|
| **ไม่กระทบ path ขายเดิม** | บิลไม่มี `memberId` / ไม่ส่ง `pointsToRedeem` = ขายเหมือนเดิม |
| **แลกแต้ม = ส่วนลด ไม่ใช่ช่องทางชำระ** | เงินสด/PP/โอนนับจาก `total` หลังลด — ลิ้นชักไม่เพี้ยน |
| **แยกตัวเลขส่วนลดมือกับแลกแต้ม** | เก็บ `redeemBaht` แยกเสมอ · `discountBaht` = ส่วนลดมือ + แลกแต้ม (รวม) |
| **ค่าเริ่มปิด** | `memberSettings.enabled` ปิด → UI แลกแต้มไม่โผล่ / server ปฏิเสธแลก |
| **OTA เมื่อพร้อม** | M2/M3 แตะ APK — ทำทีหลังเทสเซิร์ฟเวอร์+หลังร้านข้อมูลครบ หรือคู่ขนานแบบธงปิด |
| **ไม่เขียน shop cash ledger** | แลกแต้มไม่ใช่เงินเข้า — ไม่ต้องสร้างรายการบัญชีเงินสด |

## สัญญาข้อมูล (อย่าตกหล่น)

### A) เอกสาร `posSales/{saleId}`

| ฟิลด์ | เมื่อไหร่ | ความหมาย |
|--------|-----------|----------|
| `memberId` | ผูกสมาชิก / แลก / สะสม | รหัสสมาชิก (= เบอร์ตัวเลข) |
| `memberPhone` | ถ้ามี | เบอร์แสดงผล |
| `subtotal` | ทุกบิล | ยอดก่อนลด |
| `manualDiscountBaht` | **ใหม่ (แนะนำ)** | ส่วนลดมือพนักงาน (ไม่รวมแต้ม) · 0 ถ้าไม่มี |
| `redeemBaht` | เมื่อแลก | เงินส่วนลดจากแต้ม |
| `pointsRedeemed` | เมื่อแลก | จำนวนแต้มที่ตัด |
| `discountBaht` | รวม | `manualDiscountBaht + redeemBaht` (คงสูตรเดิมให้ของเก่าอ่านได้) |
| `total` | ทุกบิล | `subtotal - discountBaht` = เงินที่เก็บจริง |
| `pointsEarned` | หลัง commit (earn) | แต้มที่ได้จากบิลนี้ (คิดจาก `total` หลังลด) |
| `pointsClaimed` / `claimStatus` / … | QR สลิป | คงของเดิม (สะสมจากสแกน) |

**เซิร์ฟเวอร์วันนี้:** `nposCompleteSale` รับ `memberId` · `memberPhone` · `pointsToRedeem` แล้วคำนวณ `redeemBaht` ใน txn + เขียน `memberLedger` reason `redeem` แล้ว  
**ยังขาดฝั่งข้อมูล:** แยก `manualDiscountBaht` (ตอนนี้พับรวมใน `discountBaht`) · mapper หลังร้านบางตัวยังไม่โชว์ฟิลด์แต้ม

### B) สลิปพิมพ์ (nPos + พรีวิวหลังร้าน)

ต้องเห็นอย่างน้อยเมื่อมีการใช้แต้ม / ผูกสมาชิก:

| บรรทัดบนสลิป | แหล่ง |
|---------------|--------|
| (ถ้ามี) สมาชิก / เบอร์ท้ายใบ | `memberPhone` หรือท้าย `memberId` |
| ส่วนลด (มือ) | `manualDiscountBaht` — ซ่อนถ้า 0 |
| แลกแต้ม −X บาท (Y แต้ม) | `redeemBaht` + `pointsRedeemed` |
| ยอดสุทธิ | `total` |
| ชำระ / เงินทอน | ของเดิม |

> ถ้ายังไม่แยก `manualDiscountBaht` ในรอบแรก: แสดง «ส่วนลด» จาก `discountBaht` + บรรทัดย่อย «(รวมแลกแต้ม X)» เมื่อ `redeemBaht > 0` — **ห้าม** พิมพ์แค่สุทธิโดยไม่บอกว่าลดจากแต้ม

**พิมพ์ก่อน sync:** payload local ตอนปิดบิลต้องใส่ส่วนลด/แลกแต้มครบก่อนเรียกพิมพ์ — สลิปต้องตรงบิล

### C) หลังร้าน — รายละเอียดบิล / ประวัติ

พื้นผิวที่ต้องโชว์ฟิลด์เดียวกัน (ไม่ใช่แค่ `total`):

| พื้นผิว | ไฟล์หลัก | ต้องโชว์ |
|--------|-----------|----------|
| รายการบิล + เปิดบิล | `PosSalesReport.tsx` · `PosReceiptPaper` | สมาชิก · แลกแต้ม · ส่วนลดมือ · แต้มได้ |
| พรีวิว/พิมพ์ซ้ำ BOH | `saleToLocalReceipt` · receipt paper | เท่าสลิป |
| ประวัติเครื่อง (nPos) | `ReceiptsActivity` · reprint | เท่าสลิป |
| แท็บ QR สลิปสมาชิก | `/members` claim | อย่างน้อยสถานะเคลม + ยอด (มีแล้ว) · ถ้าบิลมี redeem โชว์ด้วยได้ |
| mapper | `pos-sales-admin.mapPosSale` · `pos-sales-report.mapPosSale` | อ่าน `memberId` · `pointsRedeemed` · `redeemBaht` · `pointsEarned` · `manualDiscountBaht` ให้ครบทั้งสองทาง |

### D) แดชบอร์ด / สรุปยอดขาย (`/pos-sales` แท็บแดชบอร์ด)

สูตรเงินที่**ต้องคง**:

| ตัวเลข | สูตร | หมายเหตุ |
|--------|------|----------|
| ยอดขายสุทธิ | `Σ total` (completed) | = เงินที่เก็บจริง — **ถูกอยู่แล้วถ้า redeem เป็นส่วนลด** |
| ช่องทางชำระ | `Σ total` ต่อ cash/PP/transfer | ไม่นับ redeem เป็นช่องทาง |
| ยอดก่อนลด (gross) | `Σ subtotal` หรือ `net + discountTotal` | |
| ส่วนลดรวม | `Σ discountBaht` | รวมมือ+แต้ม |

**เพิ่มแยก (อย่าพับหายใน «ส่วนลด» อย่างเดียว):**

| ตัวเลขใหม่ | สูตร |
|------------|------|
| ส่วนลดมือ | `Σ manualDiscountBaht` (หรือ `discountBaht - redeemBaht` ช่วงเปลี่ยนผ่าน) |
| แลกแต้ม (บาท) | `Σ redeemBaht` |
| จำนวนบิลที่มีแลกแต้ม | นับบิลที่ `redeemBaht > 0` |
| แต้มที่ตัดทั้งช่วง | `Σ pointsRedeemed` (optional กล่องสมาชิก) |
| แต้มที่ให้ทั้งช่วง | `Σ pointsEarned` (+ claim ถ้าต้องการแยกช่องทาง) |

จุดที่ต้องแก้/ต่อเมื่อมีข้อมูลจริง:

- `summarizePosSalesDetailed` (`pos-sales-report.ts`) — แยก `redeemTotal` / `manualDiscountTotal`
- `PosSalesDashboard.tsx` — กล่องสรุป: แสดง «ส่วนลด» แล้วมีแถวย่อยหรือกล่องข้าง «แลกแต้ม»
- กราฟรายวัน/สินค้า — คงใช้ `sale.total` (เงินจริง) · **ไม่** บวก redeem กลับเข้า tender
- โปรโม/ส่วนลด side panel — แยกหรือติดป้ายว่าส่วนหนึ่งเป็น loyalty

### E) รอบขาย / ปิดกะ (X·Z)

| จุด | ต้องทำ |
|-----|--------|
| `ShiftPrefs.recordSale` (local) | นับ `discountTotal` ให้รวม redeem ด้วย |
| รายงานปิดกะ / พิมพ์ X·Z | แยกหรือระบุส่วนลดจากแต้มถ้ารวมอยู่ใน discount |
| `posSessions` live patch ตอน complete | คงสะสม `totalSales` จาก net `total` (ถูกแล้ว) |

### F) `memberLedger`

| reason | เมื่อไหร่ |
|--------|-----------|
| `redeem` | ปิดบิลแลกแต้ม (มีแล้วใน txn) |
| `earn_sale` | สะสมจากบิลที่ผูกสมาชิกตอนขาย (มีแล้ว post-commit) |
| `earn_receipt_claim` | สะสมจาก QR สลิป (มีแล้ว) |
| `void_reverse` | ยกเลิกบิล — **ต้องคืนทั้ง earn และ redeem** (วันนี้คืนแค่ earn ทาง nPos · BO void ยังไม่คืน) |

หลังร้าน `/members` รายละเอียดสมาชิก: แถว ledger ควรโชว์ `saleId` / ลิงก์บิลเมื่อมี (ตอนนี้ตัดสั้น — อย่าให้ไล่บิลไม่ได้)

### G) สิ่งที่**ไม่**ต้องใส่

- ไม่สร้างรายการ shop cash ledger ตอนแลกแต้ม
- ไม่เพิ่ม paymentMethod ชนิด `points`
- ไม่บังคับแต้มบนบิลที่ไม่มีสมาชิก
- ไม่เปิด R4/ลูกค้าจริงจนกว่าเฟสข้อมูล+void ครบและคุณยืนยัน

## เคสขอบ (เช็คทุกรอบก่อนเปิดใช้จริง)

| เคส | พฤติกรรมที่ต้องการ |
|-----|---------------------|
| แลกบางส่วน | คีย์แต้ม ≤ คงเหลือ · เงินลด = ตามสูตร · เหลือจ่ายเงินสด/PP/โอน |
| ส่วนลดมือ + แลกแต้ม | เก็บแยก · สลิปแยกบรรทัด · แดชบอร์ดแยกได้ |
| ผูกสมาชิกแต่ไม่แลก | มี `memberId` · `pointsRedeemed=0` · อาจได้ `pointsEarned` |
| แลกแล้วได้แต้มบิลเดียวกัน | earn คิดจาก `total` **หลัง** ลด — ถูกโดยดีไซน์ |
| ยกเลิกบิลหลังแลก | คืนแต้มที่ตัด + ย้อน earn ถ้ามี · เขียน `void_reverse` (หรือ reason แยก redeem reverse ก็ได้แต่ต้องคืนยอด) |
| ยกเลิกจากหลังร้าน vs เครื่อง | path เดียวกันเรื่องแต้ม — ห้ามเหลือแค่ฝั่งเดียว |
| สมาชิกระงับ / ระบบปิด | lookup บอกสถานะ · ห้ามแลก |
| แต้มไม่พอ / แข่งสองเครื่อง | server txn ปฏิเสธ · UI โชว์ error ชัด |
| QR claim คนละทางกับแลกที่เคาน์เตอร์ | คนละฟิลด์ · บิลเดียวกันไม่ควรได้ earn สองทางซ้ำ (idempotent ต่อ saleId+reason) |
| พิมพ์สลิปก่อน sync ล้ม | สลิป local ตรงส่วนลด/แต้ม · sync ซ้ำไม่ตัดแต้มซ้ำ (`clientMutationId`) |

## สรุปเฟสรอบนี้ (วางให้ครบวงจรใช้แต้ม)

ลำดับทำ — **ข้อมูล/เซิร์ฟเวอร์กันพลาดก่อน → UI เครื่อง → สลิป → หลังร้าน/แดชบอร์ด → เปิดใช้**

| เฟส | โหมด | ส่งมอบ | แตะ APK? |
|-----|------|--------|----------|
| **D0** | เอกสาร+สัญญา | เอกสารนี้ · อัปเดตลิงก์ใน CRM phases · ล็อกสูตรและพื้นผิวที่ต้องโชว์ | ไม่ |
| **D1** | เซิร์ฟเวอร์/โมเดล | แยก `manualDiscountBaht` · บังคับเขียน `redeemBaht`/`pointsRedeemed`/`memberId` เมื่อแลก · void คืน redeem+earn ทั้ง nPos และ BO · mapper admin/report อ่านครบ | ไม่* |
| **D2** | หลังร้านมองเห็น | รายละเอียดบิล+พรีวิวสลิปโชว์สมาชิก/แลกแต้ม · ledger สมาชิกโชว์ `saleId` · สรุปช่วงมี redeemTotal | ไม่ |
| **D3** | แดชบอร์ด | กล่องส่วนลดแยกมือ vs แลกแต้ม · นับบิลแลกแต้ม · (optional) กล่องแต้มให้/ตัด | ไม่ |
| **M2** | เคาน์เตอร์ผูกสมาชิก | nPos: คีย์เบอร์ → `nposMemberLookup` → โชว์ชื่อ/แต้มคงเหลือ · ติดบิลเป็น `memberId` | ใช่ |
| **M3** | เคาน์เตอร์แลกแต้ม | จากยอดคงเหลือ → โชว์เงินที่แลกได้ → ยืนยันแต้ม/บาท → ส่ง `pointsToRedeem` ตอนปิดบิล · อัปเดตยอดสุทธิบนจอ+local discount | ใช่ |
| **D4** | สลิปเครื่อง | พิมพ์บรรทัดแลกแต้ม (+ สมาชิก) · ประวัติเครื่อง reprint ตรงกัน · shift discount รวม redeem | ใช่ |
| **D5** | เกตเปิดใช้ | ธง/เช็คลิสต์ร้าน · เทสเคสขอบ · เอกสารวิธีใช้พนักงานสั้นๆ · **ยังไม่** ผูก R3 พิมพ์ QR สะสมถ้าไม่พร้อม | ตามธง |

\*D1 อาจแตะ CF อย่างเดียวก่อน APK — ของเก่าที่ไม่ส่งฟิลด์ใหม่ยังขายได้

ความสัมพันธ์กับเฟสเดิม:

- **M2 / M3** ใน `members-crm-phases.md` = UI เครื่องในตารางนี้  
- **R3** (พิมพ์ QR สะสมบนสลิป) คนละเรื่องกับใช้แต้ม — ทำคู่ขนานได้หลัง D4 หรือทีหลัง  
- สะสมจาก QR หลังร้าน (R0–R2) ใช้คู่กับ M3 ได้: สะสมทางสแกน · ใช้แต้มทางคีย์เบอร์

## D1 — โมเดล + void ปลอดภัย

- [ ] `manualDiscountBaht` บนบิลใหม่ที่ส่วนลดมือหรือมี redeem (บิลเก่า: derive ได้จาก `discountBaht - redeemBaht`)

- [ ] void (เครื่อง + หลังร้าน) คืนแต้ม redeem และย้อน earn แบบ idempotent
- [ ] `pos-sales-admin` / `pos-sales-report` map ฟิลด์สมาชิกครบ
- [ ] สูตร `redeemBahtFromPoints` / ตั้งค่า `pointsPerBahtRedeem` เอกสารใน UI ตั้งค่าสมาชิกให้พนักงานเข้าใจ

**เกณฑ์จบ:** สร้างบิลเทสผ่าน CF/สคริปต์แล้วอ่านฟิลด์ครบ · void แล้วแต้มกลับ

## D2 — หลังร้านมองเห็นบิล

- [ ] UI แดชบอร์ด: ยอดสุทธิคงเดิม · ส่วนลดรวมยังมี · **เพิ่ม** แถว/กล่อง «แลกแต้ม»
- [ ] ไม่นับ redeem ในกราฟช่องทางชำระ
- [ ] อัปเดตหมายเหตุใน `pos-sales-dashboard-phases.md` ว่าส่วนลดแยกมือ/แต้มแล้ว

**เกณฑ์จบ:** ช่วงวันที่มียอดแลกแต้มตรงกับผลรวมบิลตัวอย่าง

## M2 — คีย์เบอร์ผูกสมาชิก (เครื่อง)

- [ ] จุดเข้าตอนคิดเงิน (ไม่เกะกะขายปกติเมื่อธงปิด)
- [ ] คีย์เบอร์ → lookup → โชว์ชื่อ · บัตร · **แต้มคงเหลือ** · สถานะระงับ
- [ ] ยืนยันติดบิล / ถอดสมาชิกออกจากบิลก่อนปิดได้
- [ ] ส่ง `memberId` (+ phone) ตอน `nposCompleteSale`
- [ ] ไม่บังคับแลกแต้มในเฟสนี้也能ปิดบิลได้

**เกณฑ์จบ:** บิลเทสมี `memberId` · ได้ `pointsEarned` ตามยอดสุทธิ (ถ้าเปิด earn)

## M3 — แลกแต้มตอนคิดเงิน

- [ ] จากสมาชิกบนบิล: โชว์ **เงินสูงสุดที่แลกได้** ตามสูตร + ยอดบิล
- [ ] เลือก/คีย์จำนวนแต้มหรือบาทที่จะใช้ (ไม่เกินคงเหลือและไม่เกินยอด)
- [ ] ยืนยันแล้วอัปเดตยอดสุทธิบนจอทันที
- [ ] ปิดบิลส่ง `pointsToRedeem` · ล้มแล้วไม่ตัดแต้ม · สำเร็จแล้วคงเหลือลด
- [ ] ใช้คู่กับเงินสด/PP/โอนตามยอดหลังลด

**เกณฑ์จบ:** เคสแลกบางส่วน + เต็มยอด (สุทธิ 0 ถ้าอนุญาต) ผ่านบนเครื่องทดสอบ

## D4 — สลิป + ประวัติเครื่อง + กะ

- [ ] `ReceiptFormBuilder` (และ reprint) บรรทัดแลกแต้ม / สมาชิก
- [ ] local payload ก่อนพิมพ์มีตัวเลขครบ
- [ ] `ShiftPrefs` / ปิดกะนับส่วนลดรวม redeem
- [ ] พิมพ์ X·Z ไม่ทำให้ยอดเงินสดเพี้ยน

**เกณฑ์จบ:** สลิปจริงกับบิลในหลังร้านตัวเลขตรงกัน

## D5 — เกตเปิดใช้หน้าร้าน

- [ ] เช็คลิสต์เคสขอบด้านบนติ๊กครบบนเครื่องจริงนอกชั่วโมงขายหรือเครื่องเทส
- [ ] คู่มือสั้นพนักงาน: ถามเบอร์ → คีย์ → ดูแต้ม → แลก → เช็คสลิป
- [ ] ธงเปิดเฉพาะเมื่อคุณยืนยัน · ค่าเริ่มเครื่อง/ร้านยังปลอดภัยถ้าปิดสมาชิก
- [ ] R3/R4 (QR สะสมบนสลิป / เปิดลูกค้า) **ไม่บังคับ** ในเกตนี้ — คนละปุ่มเปิด

**เกณฑ์จบ:** คุณยืนยันใช้คิดเงินจริงได้โดยไม่ทำให้ยอดวันเพี้ยน
